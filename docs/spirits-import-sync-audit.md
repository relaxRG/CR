# 烈酒库存导入、日期归属与云同步重构审计

**状态：已完成并验证**  
**适用范围：**烈酒库存盘点 Excel、当月进货 Excel/PDF、移动端导入预览、跨设备同步，以及具有相同日期风险的葡萄酒、食品供应商、备用金成本与时段分析导入。

> 本次审计确立的原则是：**日期先验证，月份从已验证日期派生；采购流水是台账的唯一可追溯来源；任何批量写入后的台账重算必须包含本批待写入数据。**

## 1. 统一日期归一化规则

共享实现位于 `lib/import/date-utils.ts`，唯一公开入口为 `normalizeImportDate(value)`。成功时返回严格的 `YYYY-MM-DD`，无法可靠判定时返回 `null`；调用方必须跳过该行或要求用户修正，**不得以“当天”替代错误日期**。

| 输入类型或格式 | 示例 | 结果 | 说明 |
|---|---|---|---|
| JavaScript `Date` | `new Date("2026-08-03T00:00:00Z")` | `2026-08-03` | 使用 UTC 年月日，避免设备时区造成前后一天偏移。 |
| Excel 日期序列号 | `46238` | `2026-08-04` | 支持有效 Excel 序列号范围，统一按 UTC 归一化。 |
| 八位紧凑日期 | `20260803` | `2026-08-03` | 年、月、日必须构成真实自然日。 |
| 年在前的分隔日期 | `2026-8-3`、`2026/8/3`、`2026.8.3` | `2026-08-03` | 可附带时间尾缀，例如 `2026/8/3 10:30:00`。 |
| 中文完整日期 | `2026年8月3日`、`2026年08月03日` | `2026-08-03` | 必须包含年、月、日。 |
| 日/月/年或月/日/年 | `31/07/2026`、`08/03/2026` | `2026-07-31`、`2026-08-03` | 当首段大于 12 时按 `DD/MM/YYYY`；其余可歧义格式按 `MM/DD/YYYY`，与常见 Excel 文本输出一致。 |
| 空日期 | 合并单元格后的空白行 | 继承上一条**已验证**日期 | 仅限同一工作表数据行；若首个有效商品行无可继承日期则跳过。 |
| 不支持或非法输入 | `2026-02-30`、`2026-13-01`、`8月3日`、任意文本 | `null` | 导入器跳过该行并在可提供提示的位置记录“日期无法识别/日期无效”。 |

### 1.1 月份归属规则

每条采购流水的 `month` 都由已验证的 `date.slice(0, 7)` 得出；跨月文件中的七月记录与八月记录不会被强制放进同一个月份。盘点快照的显示月份使用全部有效采购记录的**主月份**（出现次数最多；并列时采用最先出现的月份），而不再由第一条记录决定。

## 2. 云同步键与数据结构

审计发现原来“烈酒库存 11 键”的说法不准确：实际烈酒运行时状态只有 **10 个烈酒专属键**。第 11 个 `supplier.match.memory.v1` 是食品供应商导入的 `rawName → ingredientId` 记忆，不属于烈酒；现已移动到“餐食菜单”同步模块，避免权限范围、同步日志和数据归属混淆。

| 键 | 数据结构 | 核心字段与职责 |
|---|---|---|
| `spirits.items.v3` | `SpiritItem[]` | 酒款档案：`id`、中英文名、分类、集团、单位、规格、参考单价、启用状态、酒库关联与审计时间。 |
| `spirits.purchases.v3` | `SpiritPurchaseRecord[]` | 每笔采购流水：`month`、`date`、`itemId`、原始名、数量、单价、金额、供应商、分类/集团、来源（手工/Excel/PDF）。这是进货明细的追溯源。 |
| `spirits.ledger.v3` | `SpiritLedgerEntry[]` | 每月每酒款台账：期初、进货量/成本、消耗、期末数量/成本、关闭状态与更新时间。 |
| `spirits.refPrices.v1` | `SpiritRefPrice[]` | 按月生效的参考单价：`itemId`、生效 `month`、价格、设置时间与来源。 |
| `spirits.suppliers.v1` | `SpiritSupplierInfo[]` | 供应商卡片：名称、联系人、联系方式、地址、银行信息、自采标识及备注。 |
| `spirits.groups.v1` | `SpiritGroupDef[]` | 品牌集团定义：集团名、关键词、颜色、内置标识、创建时间。 |
| `spirits.matchMemory.v1` | `PettyMatchMemory[]` | 备用金描述到烈酒档案的确认映射：描述、酒款 ID/名称、置信度、确认时间。 |
| `spirits.selfBuyConfig.v1` | `SelfBuyConfig` | 自采导入配置：可纳入的备用金分类代码、关键词过滤开关、更新时间。 |
| `spirits.customCategories.v1` | `SpiritCustomCategory[]` | 自定义或覆盖内置分类的名称、颜色、原分类和创建信息。 |
| `spirits.groupMatchMemory.v1` | `GroupMatchMemory[]` | 原始商品名到品牌集团的人工确认映射和确认时间。 |

这 10 个键由 `SpiritsInventoryProvider` 统一加载、持久化和参与云同步。同步引擎的行为为本地 `AsyncStorage` 变更推送、远端增量拉取，以及按更新时间执行的最后写入胜出合并；应用从后台回到前台会触发节流同步，实时层使用 WebSocket 智能轮询。

## 3. 受影响逻辑、引擎与清理结果

| 范围 | 旧风险 | 新实现/清理结果 |
|---|---|---|
| 烈酒盘点 Excel | 日期文本直接截取；月份使用首条采购日期。 | 使用共享日期工具、空日期安全继承、主月份判定。 |
| 当月进货 Excel/PDF | 导入采购流水时 `itemId` 固定为空，台账重算会跳过该记录。 | 标准化名称关联既有酒款；未匹配时自动建立库存档案，再写入完整采购流水。 |

| 移动端导入预览 | 手动编辑/批量改日期仅做正则校验，`2026-02-30` 会被接受。 | 预览编辑复用共享日期工具；无效日期提示用户并拒绝保存。 |

| 食品库存入口 | 食品页“导入 Excel”曾错误跳转至烈酒旧导入器。 | 已删除错误入口。 |
| 葡萄酒库存导入 | 同类的字符串截取、Excel 序列号和首条日期决定月份风险。 | 接入共享日期工具与主月份判定。 |
| 食品供应商、备用金成本、时段报表导入 | 非法或缺失日期可被回退为当天，或原样参与月份推断。 | 接入共享日期工具；非法日期安全跳过，不再伪造当天日期。 |

## 4. Bug 根因

本问题并非单一的“日期格式不支持”，而是四类架构缺陷叠加：

1. **重复解析器分叉。** 不同入口分别处理 `Date`、Excel 序列号和文本日期，造成同一文件在不同入口得到不同结果。
2. **错误容错策略。** 缺日期或无法解析时使用“当前日期”，把源数据问题静默转化为错误月份与错误库存。
3. **数据链路断裂。** 盘点导入写了台账但未写采购流水；普通采购导入写了流水但未建立酒款关联。
4. **状态时序错误。** `dispatch` 后立即从闭包中的旧状态重算台账，导致本批数据不在汇总输入中。

## 5. 防止复发的开发规范

| 规则 | 强制要求 |
|---|---|
| 日期解析 | 所有表格导入必须调用 `normalizeImportDate`；禁止新增私有日期解析器，禁止用当前日期填补解析失败。 |
| 导入验证 | 日期、商品、数量、金额分别校验；日期无效的行必须跳过并给出可操作提示。 |
| 月份派生 | 只能从已验证的 ISO 日期派生 `YYYY-MM`；禁止直接从原始文本或“第一条记录”推断整月。 |
| 单一数据源 | 采购明细只写 `spirits.purchases.v3`，台账由采购流水和明确的盘点数据驱动；UI 不自行维护另一份采购真相。 |
| 批量状态更新 | 后续计算必须显式接收本批待写入数据，不能假设 React 状态已经在当前调用栈刷新。 |
| 同步键归属 | 键必须注册在真正拥有其数据模型的模块；同步清单、权限测试和云同步标签要同步更新。 |
| 废弃架构 | 迁移完成后立即删除旧页面、Provider、路由、键注册和测试期望，不保留注释占位。 |
| 回归测试 | 每条新增导入路径至少覆盖：日期格式、非法日期、首行空日期、合并单元格继承、跨月混合、未匹配商品、批量重算和移动端布局。 |
