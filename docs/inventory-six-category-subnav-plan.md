# 库存六类同级导航改造方案

## 目标

将“库存”从当前的六张入口卡片改为与员工模块“薪资统计 / 排班表 / 薪资预支”同等级的二级业务导航：**烈酒、葡萄酒、水果、食材、啤酒、冰块**。它们是库存模块的六个平级工作区，而不是先进入一张目录页再跳转。

店铺模块保持独立，仅管理杯具、餐具、日用品和设备；不与原料库存混合。

## 目标信息架构

```text
门店（顶级）
├─ 报表
├─ 员工
├─ 备用金
├─ 店铺：杯具｜餐具｜日用品｜设备
└─ 库存：烈酒｜葡萄酒｜水果｜食材｜啤酒｜冰块
```

库存二级导航与员工模块同层级：点击标签可直接切换内容工作区；左右滑动内容页时，活动标签同步更新。

## UI与交互

| 视口 | 二级导航 | 内容切换 | 重点边界 |
|---|---|---|---|
| 375–430pt | 顶部横向滚动分段栏；不压缩标签、不换行 | 横向分页，单次装载当前页 | 活动标签自动居中；不产生根级横向溢出 |
| ≥600pt | 居中分段栏，六项完整可见 | 逻辑分页或点击切换 | 保留各库存页的宽屏表格与筛选 |
| 直接路由 | 进入原有详情/导入页 | 返回库存模块时恢复最后活动分类 | 仍支持现有深链和扫码/导入跳转 |

每个分类标签只显示名称；当前分类的页面标题、导入、盘点、台账操作继续由该分类内容页提供。分类切换无全局刷新：只有当前页挂载且数据Store发生变化时才更新，避免同时订阅六个大库存Store造成移动端卡顿。

## 实施架构

1. 新建 `components/store/inventory-module.tsx`，定义唯一 `INVENTORY_PAGES`：`spirits`、`wine`、`fruit`、`food`、`beer`、`ice`。
2. 将六个既有 `app/*-inventory.tsx` 的可复用内容抽为各自 `*InventoryPanel`。默认路由页保留为独立屏幕包装器，避免破坏二维码、导入页、深链和返回栈。
3. 库存顶级Tab渲染 `InventoryModule`，使用 `usePersistedState("store.inventory.category.v1", "spirits")` 保存最近分类。
4. 使用与员工模块相同的 `useWindowDimensions()`、页宽钳制和无动画宽度重对齐模式；禁止模块级 `Dimensions.get()`。
5. 店铺四类与库存六类共用原有Store与现有路由，不迁移、不复制、不重置任何库存数据。

## 权限与数据边界

库存六类全部继续使用 `store_ops` 权限；店铺同样使用 `store_ops`。本地单机模式全量可见。不存在新增同步键、库存迁移或权限字段；本次仅改变入口层次和组件渲染方式。

## 性能与测试

| 测试 | 断言 |
|---|---|
| 375/390/430pt | 六标签可滑动、活动状态准确、无根级横向溢出 |
| 1024/1280/1440pt | 六标签完整显示，宽度变化后当前页不跳错 |
| 路由回退 | 导入/详情返回后恢复原分类，不重新初始化其他五类Store |
| 权限 | `store_ops`缺失显示统一无权提示，本地模式全量可见 |
| 性能 | 快速切换六类时只订阅活动分类；不并行触发六个库存计算或导入扫描 |
| 回归 | 烈酒台账移动抽屉、葡萄酒导入、食材低库存、啤酒/冰块/水果预警全部保持原行为 |

## 不做的事情

本方案不修改任何库存数据模型、导入格式、盘点公式、采购同步或门店物资四类的路由。它不使用全局缩放，也不会把六个复杂表格同时预渲染在375pt设备上。
