# 排班表响应式分页重构审计

## 目标

本次重构解决排班表在网页放大缩小、桌面分屏及横竖屏切换后，日历网格、考勤概况、薪资预支页与底部导航不能按同一宽度基准更新的问题。业务排班、考勤、薪资、预支及月度归档逻辑不在本次改动范围内。

## 根因

排班页面原先存在两套分页宽度来源。劳动模块外层的“薪资统计 / 排班表 / 薪资预支”使用 `useWindowDimensions().width`，而排班内部的“排班表 / 考勤概况”使用模块加载时执行一次的 `Dimensions.get("window")`。后者在网页缩放、容器尺寸变化和旋转后不更新，导致内外页宽、分页偏移量和实际可视区域不一致。

固定宽度子页还同时使用了 `flex: 1`，使横向分页子项既有显式宽度又可以参与剩余空间分配。在不同缩放级别下，这会放大错页、日历裁切和右侧页面露出的风险。

## 受影响逻辑与替换结果

| 区域 | 旧实现 | 新实现 |
|---|---|---|
| 静态宽度 | 全局 `SCREEN_W = Dimensions.get("window").width` | 已删除；不再有模块加载时宽度快照。 |
| 外层三页分页 | 通过 `winW` 定位，但子页同时使用 `width + flex: 1` | 子页统一使用 `width: winW + flexGrow: 0 + flexShrink: 0`。 |
| 内层排班分页 | 使用静态 `schPageWidth = SCREEN_W` | `SchedulePage` 接收外层实时 `pageWidth`，内部两页使用同一值。 |
| 宽度变化后的页位置 | 外层仅依赖旧偏移，内层不对齐 | 外层和内层均记录当前页索引；宽度变化后以 `index × currentWidth` 无动画对齐。 |
| 控制栏 | 单行布局在窄宽/缩放下可能挤压 | 增加 `flexWrap` 与间距，允许控件换行，不挤压日期网格。 |
| 回归定位 | 无稳定页宽测试节点 | 新增排班/考勤与外层三页测试标识，供H5实际测量。 |

## 统一布局规则

1. 横向分页的每个子页必须使用当前容器的实时宽度；禁止在模块顶层读取并缓存 `Dimensions.get`。
2. 有显式 `width` 的横向分页子页必须设置 `flexGrow: 0` 和 `flexShrink: 0`，禁止同时依赖 `flex: 1`。
3. 宽度变化后必须保持当前逻辑页，而不是沿用旧像素偏移量。
4. 业务内容区与底部导航不共享固定值；内容页使用容器全宽，导航继续由应用根布局负责。
5. 控制栏可换行，日历网格的姓名列保持固定，七个日期列在剩余实时宽度中均分。

## 防回归覆盖

### 单元/源码护栏

`tests/schedule-responsive-pager.test.ts` 断言：

- 不再出现静态 `Dimensions.get("window")` 或 `SCREEN_W`；
- 外层三页与内层排班两页均使用实时 `useWindowDimensions()` 页宽；
- 外层和内层均在宽度变化后重新对齐当前页；
- 控制栏允许换行。

### H5视觉与布局回归

`scripts/h5-schedule-correction-e2e.mjs` 执行：

- 375、390、430pt移动端下排班工具栏、编辑模式、日历与核心报表页面无根级横向溢出；
- 1024、1280、1440px桌面连续宽度调整下，外层排班页、内层排班页及考勤页宽度均等于当前页面宽度；
- 连续调整宽度后仍保持排班表当前页，不露出薪资预支页；
- 烈酒库存导入同步、员工筛选标签和月度归档三态继续通过原有多尺寸验证。

## 性能与状态同步说明

宽度重对齐只在实际页宽变化时调用一次无动画 `scrollTo`，不参与排班格子渲染、考勤计算或薪资重算。当前页索引由横向分页的动量结束事件维护，避免缩放过程中高频写状态。现有排班、考勤面板和同步性能回归保持通过。

## 开发规范

后续新增横向分页、分栏编辑器或表格式大屏页面时，必须复用实时容器宽度、建立缩放测试节点并覆盖移动端与桌面宽度变化。不得使用模块顶层的静态屏幕尺寸作为可缩放布局的页宽或分页偏移量。
