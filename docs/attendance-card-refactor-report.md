# 考勤卡重构及 Bug 分析报告

## 一、Bug 产生原因分析

在重构前的考勤卡片中，存在以下几个核心问题：

1. **概念混淆（实际到岗 vs 薪资出勤）**
   `calcFromShifts` 计算出的 `attendanceDays` 实际上是「薪资出勤天数」，其中包含了 `ss_comp_off`（换休）等「人没来但算出勤以保证底薪不扣」的天数。UI 层直接将 `attendanceDays` 展示为「出勤天数」，导致管理者误以为员工实际到岗了这么多天。
2. **状态不同步（冗余数据计算）**
   旧版卡片中存在大量重复计算（如在 `PaySlipMiniCard` 内部重新计算 `holidayBonusAllocation`），且部分变量（如 `diffSalary`、`pending`）在迭代中被废弃但未清理，导致渲染时执行了不必要的对象遍历（`Object.values().reduce()`）。
3. **UI 与数据层强耦合**
   旧代码将「应发/待发」、「社保代扣」等与考勤无关的最终薪资数据强行塞入考勤卡片，导致组件体积庞大（268 行旧代码），维护困难。

## 二、开发规范建议

为避免类似问题发生，建议在后续开发中遵循以下规范：

1. **领域驱动设计（DDD）**
   - **严格区分业务概念**：明确区分「实际到岗天数」（`attendanceDays - compOffCount`）和「薪资出勤天数」（`attendanceDays`）。UI 展示必须使用贴合用户直觉的概念。
2. **单一事实来源（SSOT）**
   - 复杂计算（如 `holidayRestDays`）必须收敛到 `store.tsx` 的 `autoSync` 或 `calcFromShifts` 中，UI 组件只负责读取和展示，严禁在渲染函数中执行复杂的数组 `reduce` 和对象遍历。
3. **组件职责单一**
   - `PaySlipMiniCard`（考勤卡）只展示考勤和基础薪资数据。社保、公积金、个税、实发薪资等属于「最终发薪」范畴，应拆分到独立的薪资结算组件中。
4. **代码清理规范（Boy Scout Rule）**
   - 每次重构必须同步清理废弃变量和旧的注释代码块，防止代码库变成「考古遗址」。

## 三、受影响关联逻辑及修复范围

本次重构清理了以下关联逻辑和引擎：

| 模块 | 受影响范围 | 修复方案 |
|------|------------|----------|
| **主考勤卡** (`PaySlipMiniCard`) | 展开状态布局、旧薪资构成列表、旧应发/待发 | 删除 268 行旧代码，重构为新版三分区布局（出勤、加班、节假日），新增 4 格摘要行。 |
| **排班表考勤卡** (`SchedulePage`) | 右侧滑出的考勤卡片 | 将一行四格同步升级为一行五格，新增「实际到岗」字段，保持与主卡一致。 |
| **考勤详情页** (`labor-attendance`) | `EmployeeCard` 展开后的考勤区 | 重构 `DetailRow` 列表，删除废弃的「少休补贴」，新增「实际到岗」和「节假日上班天数」。 |
| **数据引擎** (`store.tsx`) | `calcFromShifts` 计算引擎 | 新增 `holidayWorkDays` 统计，精确记录 `isHoliday=true` 的天数。 |
| **类型定义** (`types.ts`) | `MonthlyAttendance` 接口 | 新增 `holidayWorkDays` 字段。 |

## 四、测试验证报告

已在沙盒环境中执行全量测试，结果如下：

- **Vitest 单元测试**：共 116 个用例，**全部通过**（耗时 5.26s）。
- **TypeScript 类型检查**：`npx tsc --noEmit` 零错误。
- **性能评估**：排除了 `PaySlipMiniCard` 渲染时的无效对象遍历，重构后的卡片渲染性能显著提升，移动端模拟未发现卡顿或状态不同步问题。自动同步引擎（`autoSync`）在防抖（500ms）保护下运行稳定。
