# 全系统复杂表格与多列报表移动端适配优先级清单

## 优先级原则

优先级由三个因素共同确定：移动端首屏是否包含核心决策信息、是否存在多列横向浏览或嵌套滚动、数据写入后是否可能因布局而不可见。完整逻辑页分页与局部数据横滑必须采用不同策略。

| 优先级 | 区域 | 当前风险 | 目标模式 | 计划状态 |
|---|---|---|---|---|
| P0 | 员工模块：排班表/考勤概况嵌套分页 | 缩放或分屏后内外页宽不同，可能错页或裁切。 | 实时页宽 + 统一分页工具 + 当前页重对齐。 | 已完成。 |
| P1 | 烈酒库存：月度14列表格 | 375–430pt下关键列需要横滑才能看到，信息密度过高。 | 紧凑主列表（品名、期末库存、期末成本）+ 完整详情抽屉；宽屏保留14列。 | 本轮实施。 |
| P2 | 烈酒库存：当月进货供应商详情 | 采购日期、商品、集团、数量、单价与成本在手机上同时展示密度高。 | 保留供应商分组；商品、数量、金额主列；编辑字段移入采购详情抽屉。 | 下一轮。 |
| P2 | 烈酒库存：盘点录入与差异处理 | 多个可编辑数值列和实际期末库存输入容易横向挤压。 | “酒款身份 + 系统期末 + 实盘数量”三列主界面；差异、成本和备注进入抽屉。 | 下一轮。 |
| P3 | 通用库存/食品库存明细 | 目前以卡片与局部表格为主，暂无根级溢出。 | 维持卡片优先；若列数超过6，复用紧凑列表/详情抽屉模式。 | 监测。 |
| P3 | 时段成本分析与月度经营报告 | 数据卡和报表块可读性已通过移动端回归，但宽屏信息密度可进一步提高。 | 移动端保留卡片分组；桌面可增加可选对比表，禁止嵌套整页分页。 | 监测。 |
| P4 | 筛选Chip、图例、配方卡、月份条 | 属于内容浏览而非业务逻辑页。 | 局部横滑、换行与文本收缩；不引入分页工具。 | 维持。 |

## 统一实施规则

> 超过六个业务决策列的数据表，必须在窄屏设计“身份主列 + 两个关键指标 + 详情入口”；不允许把桌面宽表按比例压缩到手机上。

所有多列报表必须以一个纯展示模型作为紧凑列表、详情抽屉和宽屏表格的共同输入。不得在抽屉或移动端行内重复计算成本、库存、采购或薪资金额。

| 检查项 | 通过标准 |
|---|---|
| 根级宽度 | 375/390/430pt下 `rootScrollWidth` 和 `bodyScrollWidth` 不大于视口。 |
| 主列可见性 | 无横滑时即可看到身份、状态和两项关键指标。 |
| 完整性 | 任意宽屏表格列均可通过抽屉/详情访问。 |
| 写入同步 | 导入、编辑、盘点后，主列表、详情与宽表显示同一份最新Store数据。 |
| 性能 | 长列表使用稳定ID与虚拟化/分段渲染；宽度变化不触发业务重算。 |

## 后续迭代顺序

第一阶段完成烈酒月度台账的紧凑列表与详情抽屉；第二阶段复用同一展示模型处理供应商采购详情与盘点输入；第三阶段为其他库存类模块提供可选的紧凑表格组件。每阶段均需增加375/390/430ptH5交互回归和一组长名称、负值、导入后刷新场景。
