# 当前月薪资安全强制重算方案

## 结论

可以提供“**强制更新并重新计算本月薪资**”按钮，但它不能做成“删除所有月份数据”的按钮。正确语义是：**仅对当前选择的 DRAFT 月执行可审计的全量重建；保留业务控制字段；先生成本地加密恢复快照；冻结月和调整月禁止执行。**

成熟薪资产品通常把未最终确认的薪资批次视为可审计草稿，而已最终确认的薪资批次必须通过差额或正式调整处理，不能静默重写。[1]

## 建议位置与交互

按钮放在“员工 → 薪资统计”月选择器右侧、现有“对比”按钮旁，使用次级危险色样式：

> **重新计算本月**
> 仅重新生成 2026年8月的草稿薪资；不会修改已确认发薪或其他月份。

点击后先打开预检弹窗，显示：员工数、将重建的薪资单数、检测到的旧金额差异数、是否有零出勤日补贴、是否有未同步控制字段。第二次确认文本必须为“重新计算 2026年8月”，避免误触。

## 严格范围

| 数据 | DRAFT重算动作 | FROZEN / ADJUSTING |
|---|---|---|
| 当月排班、考勤 | 只读取，按现有排班重算考勤 | 不修改 |
| 当月薪资单 | 删除当前DRAFT聚合结果并使用控制字段重建 | 不删除、不重算 |
| 补贴/KPI控制字段 | 保留 `allowanceOverrides`、`allowanceDetails`、`workKPISelections`、`revenueActuals` | 保留历史 |
| 已预支、备用金已付、调休兑现、节假日分配 | 保留并纳入新公式 | 不修改 |
| 其他月份薪资单 | **绝不读取后删除，也不改写**；仅作为同年度累计税历史输入 | 不修改 |
| 历史规则 | 不恢复已废弃规则，不迁移旧聚合字段 | 不修改 |

“误判或误识别的其他个月”不能被本月按钮直接删除。正确做法是提供单独的**跨月异常清单**：只列出检测结果（例如月份外预支、错误的旧聚合金额），每个月必须单独选择、单独确认、单独留痕。这样不会因为八月重算误删七月已发薪历史。

## 原子执行流程

```text
预检 → 创建本月恢复快照 → 获取月操作锁
  → 重新计算当月每位员工考勤
  → 基于唯一结算引擎重建每张DRAFT薪资单
  → 校验综合额外 / 应发 / 实发闭环
  → 原子replaceMonthAttendances + replaceMonthPaySlips
  → 写入审计记录 → 展示差异报告
失败 → 恢复本月快照，不触碰任何其他月份
```

实现必须复用：`calcFromShifts()`、`buildPaySlipDraft()`、`settlePayrollExtras()`、`getDraftPayrollCumulativeTaxInputs()`。按钮自身不得另写薪资公式。

## 防护与验收

1. 当前月不是 `draft` 时按钮禁用，并提示“已确认发薪请使用差额调整”。
2. 操作期间全屏禁用，使用现有月份操作锁，防止连续点击或同步并发。
3. 预检和结果均输出差异：瑞雪工作绩效 `0 → 1700`、张忠洋饭补 `15 → 0` 等。
4. 重建后逐员工验证：`综合额外 = 补贴合计 + 工作绩效 + 业绩绩效 + 奖惩小计`，且 `grossSalary` 使用同一口径。
5. 任一员工重建失败时，恢复同一月份全部考勤和薪资单快照；不产生部分重算。
6. 审计记录只保存月份、操作者、受影响员工数、差异摘要和快照ID，不保存令牌、银行卡或完整业务明细。

## 为什么不能“全部删除后重新同步”

完全删除会丢失有效的人工控制字段、已预支、调休兑现、节假日分配和已关联备用金，也会破坏冻结月审计。正确的“清除旧数据”只应指**删除可由公式重新生成的DRAFT聚合金额**，不是删除控制字段或跨月历史。
