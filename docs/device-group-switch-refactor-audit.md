# 同步组安全切换重构审计与发布前验收

**范围：** 本文覆盖设备退出同步组后被隐式创建为主设备、已是主设备却无法加入其他同步组、A组本地状态可能在切换时进入B组，以及由旧健康标识造成的版本误判。审计对象为客户端成员资格、普通同步引擎、实时轮询、照片文件、设备管理界面、Worker/D1 协议、测试与日志链路。

## 1. 受影响逻辑、替换结果与旧代码清理

| 领域 | 旧问题或冲突路径 | 新实现 | 清理与防回退措施 |
|---|---|---|---|
| 设备身份初始化 | Provider 启动、重试和前后台回归会调用隐式注册路径，未配对设备被创建成新组主设备 | Provider 仅同步已有 `DeviceInfo`；未配对状态保持纯本地模式；创建组只能显式调用 `createNewSyncGroup()` | 删除 `getOrCreateDevice()` 与客户端隐式签名密钥；删除固化旧行为的 `sync-rejoin-lifecycle.test.ts` |
| 配对与切组 | 主设备使用普通 `pairWithCode()` 时可能直接覆盖成员资格，缺少原组交接、目标快照与写入停机 | `switchToAnotherGroup()` 使用准备、提交、完整拉取替换、恢复四阶段状态机 | 配对页仅在未配对时保留 `pairWithCode()`；已有成员资格始终走原子切组 |
| 主设备角色 | 主设备无法安全离开原组，或旧角色更新路径不能一致处理交接 | 设备管理页要求选择原组新主设备；Worker 原子调整设备角色与 `device_groups.owner_device_id` | 角色更新端点统一支持 `owner` 交接；无其他设备时明确提示旧组将无活跃主设备 |
| 常规同步 | 脏键、LWW 首轮合并和普通推送在成员资格切换窗口可能把A组残留带入B组 | `beginGroupSwitchWriteBarrier()` 冻结写入、清除旧脏键；`hydrateTargetGroupSnapshot()` 仅接受B组完整快照 | 增加跨组隔离测试，断言A组键、时间戳和脏队列不能进入B组 |
| 实时轮询 | 模块级轮询请求异步返回后可能在切组后继续触发回调 | `realtimeEpoch` 代次屏障；停止、登出、切组重置时递增；旧请求结果直接丢弃 | 新增延迟请求回归测试，验证旧轮询不得触发目标组状态更新 |
| 照片文件 | `recipe-photos/` 全局目录会让新拍照片与目标组下载复用同一物理路径 | 新照片、照片下载、URI修复与上传去重均按 `groupId` 分区；目标水合仅下载 | 旧无分组目录只允许当前组普通上传路径单向迁入；目标组 `download-only` 不读取旧目录 |
| Worker / D1 | 客户端没有原子服务端切换支持，邀请码消费、源令牌撤销和目标成员创建可能各自成功/失败 | Worker 维护 `group_switches`、`group_switch_events`、邀请码保留字段与幂等恢复查询 | 迁移只新增结构；提交后只允许继续B组水合，禁止自动恢复A组 |
| 健康检查 | 静态 `version: v3` 与实际Cloudflare版本不一致，造成上线状态误判 | 健康接口更新为 `version: v4`、`release: group-switch-safe` | 新增健康标识回归护栏；Cloudflare控制台版本仍是权威部署版本 |
| 日志与隐私 | 故障难关联，且若记录原始异常会有泄露令牌或业务值风险 | `switchId` 贯穿客户端诊断与Worker审计；日志仅保存错误码和脱敏元数据 | 客户端保留120条、Worker保留90天；禁止记录业务JSON、邀请码、令牌与恢复票据 |

## 2. Bug 根因

根因不是单点UI错误，而是**设备身份、同步组成员资格与本地同步状态被错误当作同一生命周期对象**。旧架构中，未找到本机成员资格会触发“帮助性”自动注册；这使“退出一个组”的真实语义变成“立即在另一个新组中成为主设备”。与此同时，普通配对路径只处理“未配对设备加入”，没有区分“已有A组成员资格的设备加入B组”，导致数据替换、角色交接和旧状态阻断均无明确事务边界。

第二个根因是状态作用域不完整。脏键、轮询时间戳、上传去重集合和照片目录曾含有模块级或无分组状态。即使成员资格已经变为B组，这些A组状态仍可能在异步任务返回时继续工作。最后，Worker缺乏对“创建B成员、撤销A成员、消费邀请码、可恢复状态”的服务端协议，因此客户端无法可靠判断断网或强退后应该恢复A组，还是继续完成B组水合。

## 3. 新的开发规范

| 规则 | 强制要求 |
|---|---|
| 身份与成员资格分离 | 设备安装身份可以长期存在；同步组成员资格必须显式创建、显式切换、显式撤销，禁止启动时推断并创建。 |
| 一切跨组变更必须有代次 | 异步任务、定时器、轮询、缓存写入和Store重载必须持有当前成员资格或epoch；返回时二次校验，不一致即丢弃。 |
| 首次加入目标组只拉取替换 | 目标完整快照未经校验前，禁止LWW、普通推送、冲突弹窗和照片上传。 |
| 服务端提交幂等 | 必须使用 `switchId`、恢复票据哈希和可查询状态；网络超时后重试不能产生第二个目标成员。 |
| 主角色退出需明确交接 | 原组有其他活跃设备时，必须由用户选择交接目标；无其他设备则显示旧组后果并二次确认。 |
| 分组文件物理隔离 | 文件路径、上传去重键、缩略图缓存和离线资源必须包含 `groupId`；旧目录只能受控单向迁入。 |
| 日志只存安全诊断 | 仅记录稳定错误码、时间和切换关联ID；严禁写入数据内容、令牌、邀请码、照片二进制或恢复票据。 |
| 发布前回归门槛 | 必须通过类型检查、全量测试、跨组故障注入、Worker语法校验、移动端多尺寸验证；健康接口标识必须与代码版本一致。 |

## 4. 横向应用结论

本次修复已应用到所有发现的相同风险模式：普通同步引擎、实时轮询、照片上传/下载/路径修复、新增照片保存、设备管理角色变更、未配对启动、配对页入口、Worker邀请码和D1恢复记录。`AsyncStorage.clear()` 出现在“用户明确选择清除全部本地数据”的数据管理与危险操作页面，属于显式破坏性动作，不会在切组流程中调用；该路径保持独立，避免将“退出组”“切换组”“清空本地数据”混为一谈。

## 5. 测试与移动端验收

自动化测试包括：A→B零泄漏、完整快照覆盖、提交后断网、提交前强退、恢复票据无效、主设备交接、未配对启动、配对页安全分流、照片目录隔离、健康版本标识和实时轮询旧代次拦截。另有 Python SQLite 故障注入，按D1关系模型验证成员撤销、邀请码一次消费和重复提交幂等性。

移动端人工验收应在iPhone SE（375pt）、390pt与430pt上进行：进入设备管理时“加入其他同步组”按钮应完整可见；主设备存在其他成员时应弹出交接选择；输入目标码后应出现阻塞态且禁止重复点击；断网或强退重开后应显示恢复提示而不是自动变成主设备或把旧数据上传。H5自动导出在当前沙箱环境停滞，故其多尺寸脚本应在CI或开发机上补跑；这不替代已通过的单元、集成和故障注入测试。
