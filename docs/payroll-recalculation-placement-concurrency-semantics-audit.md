# 薪资强制重算入口、并发与语义审计

## 入口位置结论

“重新计算本月”**尚未实施到UI**，因此当前没有错误占位或隐藏按钮。既定方案中的目标位置位于：

```text
员工 → 薪资统计 → 员工管理 | [弹性空白] | [对比] [重新计算本月] [导入] [导出]
```

对应容器是 `app/labor.tsx` 的 `EmployeeRosterPage` 工具栏。目前实际顺序为“员工管理、弹性空白、对比、导入、导出”。因此按钮应插在 **对比与导入之间**，而不是月份标题旁边。这样它与同为“当前薪资视图操作”的对比相邻，又不混入月份切换器。

移动端不能直接新增一个带文字的横向按钮，否则375pt会挤压员工管理与对比控件。建议使用34×34的循环箭头图标按钮，`accessibilityLabel="重新计算本月草稿薪资"`；点击后弹出明确的确认抽屉。在≥600pt宽度显示“重新计算本月”文字，<600pt只显示图标和红点预检数量。按钮仅在DRAFT显示；FROZEN显示锁图标和“已确认发薪，请使用差额调整”。

## 多员工并发重算覆盖

| 场景 | 当前覆盖 | 结论 |
|---|---|---|
| 同一月份重复点击确认发薪 | `month-close-concurrency-and-performance.test.ts` | 已覆盖；月操作锁拒绝重入。 |
| 不同月份操作同时执行 | 同一测试 | 已覆盖；锁按月份隔离，不误阻塞不同月。 |
| 归档动作异常 | 同一测试 | 已覆盖；`finally`释放锁，不永久卡死。 |
| 2000名员工冻结快照 | 同一测试 | 已覆盖；索引构造线性完成。 |
| 多员工DRAFT逐人重建 | 新的薪资卡对账为同步串行写回 | 当前不会产生Promise并发写入，但**尚无专门的批量重算事务测试**。 |
| 两次“重新计算本月”快速点击 | 未来按钮未实施 | 必须新增。 |
| 两台设备同时强制重算同月 | 当前客户端锁不足 | 必须由Worker/D1 Compare-and-Swap或重算版本号处理。 |

当前DRAFT卡片对账在单一React运行时内是**串行for循环 + 幂等差异判断**，不会产生员工之间的写入冲突；但它是逐员工 `upsertPaySlip`，不是原子批次。未来“重新计算本月”不能复用这种逐条写入方式，必须采用：月级操作锁 → 本月快照 → 计算全部员工结果 → 一次性 `replaceMonthPaySlips` → 审计记录。任一失败则恢复同月快照。

跨设备风险仍存在：本地 `createMonthCloseOperationGate()` 明确只解决单客户端重入。未来强制重算上线前，Worker必须提供 `expectedRevision` 的CAS或月度`recalculationRunId`租约；否则两个设备会发生最后写入覆盖。该风险是**未来功能的阻塞条件**，不是当前卡片自动对账的已知数据损坏问题。

## 文字语义歧义

| 现有/候选措辞 | 歧义 | 建议替换 |
|---|---|---|
| 强制刷新 | 容易被理解为只刷新页面，也可能被理解为删除所有数据 | **重新计算本月草稿薪资** |
| 清空旧数据 | 容易被理解为删除控制字段、预支或历史月份 | **清除本月可再生的计算结果，保留规则、预支与人工确认项** |
| 删除其他个月误判数据 | 风险极高，不说明范围与冻结保护 | **扫描跨月异常，逐月确认处理** |
| 综合额外 | 单独出现时不说明组成 | 首次展示为 **综合额外（补贴＋工作绩效＋业绩绩效＋奖惩）**，卡片保留短名 |
| 绩效补贴 | 必须明确为补贴与两类绩效的总和，不能误写成仅页面分组 | **绩效补贴 = 补贴合计 + 工作绩效 + 业绩绩效**；金额字段继续分别显示三个组成部分 |
| 本月 | 在查看历史月时可能指自然当前月或所选月 | 全部改为 **所选月（2026年8月）** |
| 安全恢复加入 | 不说明会替换本机数据 | **恢复加入目标组（本机数据将先备份，再替换为目标组数据）** |

## 实施前必须补齐的测试

1. 50名员工本月重算时，只触发一次 `replaceMonthPaySlips`，而不是50次写入。
2. 双击重算按钮，第二次被月锁拒绝且不会生成第二个快照。
3. 第27名员工重建抛错时，整月考勤和薪资单恢复到执行前快照。
4. FROZEN与ADJUSTING月按钮不可执行，并验证不产生任何持久化写入。
5. 两个模拟设备带相同`expectedRevision`同时提交，只有一个成功；另一个收到`PAYROLL_MONTH_REVISION_CONFLICT`。
6. 375/390/430pt下工具栏图标按钮、确认抽屉、锁定提示均无横向溢出或标签截断。
