# 库存店铺工作台：移动端网页产物审计

**审计对象**：当前主分支的 Expo Web 静态导出产物（`npx expo export --platform web`）。

> 本报告评估的是H5静态产物，不等同于iOS IPA或Android AAB原生包体积。它可用于发现JavaScript、路由静态页和资源加载风险；原生包体积需在正式EAS构建后单独检查。

## 2. 冗余代码检查

以下已删除标识未出现在打包主入口：

- `beer-ice-inventory`
- `useCompactLedger`
- `进入烈酒管理`
- `进入设备管理`
- `lib/sync/provider`

`alertThreshold`在主入口中仍有一个标识，来源是历史持久化数据的单向剥离函数。该函数在加载旧数据时删除字段，未包含低库存计算、表单、导入、展示或预警功能；保留它是防止旧值同步写回的必要删除保护。

结论：已删除的旧库存页面、旧紧凑分支、旧中间入口和旧同步Provider未被H5主入口重新打包。当前未发现废弃功能代码重新进入产物。

## 3. 性能风险与优先级

### P0：主入口过大

主入口约7.02 MB未压缩、1.71 MB gzip，是当前首屏加载的主要风险。H5导出只有一个明显主入口块，说明部分重型页面模块仍进入公共加载路径。

建议：将PDF、XLSX解析、大型导入预览、图表/分析和仅在独立页面使用的编辑器改为动态加载。不得在库存工作台首屏静态导入这些模块。PDF已独立为约413 KB资源，是正确方向，应保持按需加载。

### P1：静态路由HTML重复

71个静态HTML文件合计约4.15 MB。该开销主要影响静态站点发布和缓存占用，不等于单次移动端首屏下载。若H5部署的路由数量继续增长，应评估使用共享壳或减少不需要预渲染的开发/内部路由。

### P1：图标字体

Material Icons字体约357 KB。只有在图标使用范围已明确且不影响现有图标回退时，才考虑子集化；不得为追求体积删除正在使用的图标字体。

### P2：长列表渲染

当前十类工作台只挂载当前分类，避免十类页面同时渲染。若任一分类的单月记录超过80行，应将长列表迁移至`FlatList`并使用稳定`keyExtractor`、`React.memo`行组件和延后分析计算。不要在本次布局修复中提前引入无数据依据的虚拟化重写。

## 4. 仍需真机验证的边界

H5回归已确认375、390、430pt下十类工作区无根级横向溢出、分类切换成功且库存月份保持。但H5不能替代以下原生指标：

- iOS/Android首屏TTI与JS线程帧率。
- 系统字体放大到200%时的真实文字换行与安全区。
- 大量真实采购/台账记录下的内存与滚动帧率。
- 弱网/断网恢复下的同步队列和最终送达。

在下一次允许创建TestFlight构建后，应使用低端真机、200%字体、弱网和至少80条单月记录进行验收。
