## 本轮完成范围

本轮针对 Web 首包、Excel/PDF 导入导出依赖以及 AsyncStorage 水合路径完成了低风险高收益改造，并保留所有用户可见路由、深链、同步键和业务数据语义。

## Web 构建对比

构建命令：`CI=true npx expo export --platform web`。

| 指标 | 重构前 | 重构后 | 变化 |
|---|---:|---:|---:|
| 首入口 JavaScript | 6,438,077 B | 6,339,390 B | -98,687 B（-1.532%） |
| 全部 JavaScript 总量 | 6,441,064 B | 6,442,382 B | +1,318 B（+0.020%） |
| Web 动态分块数 | 4 | 14 | +10 |

总量小幅增加来自动态分块运行时与共享模块元数据。首入口下降而总量近似持平，说明用户未触发导入导出功能时可少下载并少解析相应模块；用户点击后再加载对应分块。

## 离线缓存优化

`usePersistedState` 现在对界面偏好写入使用 180ms 防抖，组件卸载时强制落盘，并保证水合期间的本地交互优先于旧缓存。配方仓库首次水合从 7 次本地读取收敛为 1 次 `multiGet`；同步后的配方重载从 6 次读取收敛为 1 次 `multiGet`。

业务事实仍使用 AsyncStorage，原因是现有 95 个同步键、备份、业务组隔离和迁移机制以其为事实存储层。MMKV 只适合未来对非同步、可重建、高频 UI 偏好键做局部试点，不应直接替换业务事实层。

## iOS 启动测量边界

当前环境没有 `xcrun`、`simctl`、`idevice_id` 或 `ios-deploy`，无法在 iOS Simulator 或真机中输出真实冷启动毫秒数。可量化的启动 I/O 工作量已收敛，但实际 iOS 启动时间必须在具有 Instruments 或 Xcode 的环境中测量。

下一次真机验收应记录：进程启动到首帧、首帧到首次可点击、首次点击响应、首个 Tab Provider 水合完成、JS 堆与主线程长任务。当前根布局仍有 39 个 Provider；下一阶段应将其迁移到五个 Feature Provider 边界，以进一步减少首轮水合范围。
