# 复杂嵌套表格移动端适配审计

## 范围与结论

本次审计区分“完整逻辑页分页”和“局部内容横向浏览”。响应式分页工具只能用于前者；将其套用到表格、标签和卡片横滑会破坏用户浏览宽列数据的能力。

当前系统中唯一使用多级完整页面分页的区域是劳动模块，已在 `app/labor.tsx` 完成统一实时页宽重构。其余横向滚动区域均为局部内容浏览，不存在与排班表相同的“内外分页页宽错位”问题。

## 高优先级：烈酒库存多列台账

烈酒库存包含多个局部横向表格，其中月度库存台账约14列，采购库存对比表约8列，供应商采购明细也有多列。它们使用垂直外层滚动加局部横向表格滚动，属于正确的表格浏览模式，不能改为整页分页。

当前H5回归已验证375/390/430pt下库存台账和当月进货详情均无根级横向溢出，导入商品与采购记录可见。但是，局部横滑需要用户移动后才能看到关键成本列，属于可用性优化而非缩放错位缺陷。

建议的下一轮优化为：将“品名/分类”固定为视觉主列，优先展示期末库存和成本，低频的期初与参考价格列折叠到“更多”或详情抽屉；在表格首屏增加“左右滑动查看完整台账”提示，并给局部横滑增加渐隐提示。这不应使用完整分页工具。

## 中优先级：采购及供应商明细表

烈酒采购明细有日期、商品名称、集团、数量、单价、应收增加等固定宽度列。当前局部横滑适合数据密度需求，但在375pt下需要优先保留商品名称和数量；建议后续实现卡片/表格模式切换，或把可编辑成本列置入详情抽屉。

供应商、通用库存和餐具库存页面的横向滚动主要用于筛选Chip、操作按钮或局部输入控件。通用库存主台账以纵向卡片分组展示，不构成复杂嵌套表格风险。

## 低优先级：内容横滑组件

配方卡、标签、快速筛选、月份选择、颜色选择和图表图例均是内容横滑，不代表完整逻辑页面。它们继续使用局部 `ScrollView horizontal`、文本收缩和局部最小宽度；禁止引入 `pagingEnabled` 或整页宽度偏移逻辑。

书籍阅读器使用动态 `useWindowDimensions` 和独立WebView翻页逻辑，不是React Native横向分页容器；当前不需要迁移到 `responsive-pager.ts`。若未来改为RN `ScrollView pagingEnabled`，必须遵守统一分页规则。

## 回归建议

| 区域 | 应验证的内容 |
|---|---|
| 劳动多级分页 | 375/390/430pt、1024/1280/1440px连续宽度变化；当前页不变；内外页宽一致。 |
| 烈酒多列台账 | 根级不溢出；局部表格可横滑；品名、期末库存与采购记录可见；导入后数据同步。 |
| 采购明细表 | 长商品名两行截断；局部横滑不阻断垂直滚动；编辑按钮可点击。 |
| 卡片/Chip横滑 | 局部滚动存在但根级无横向溢出；不使用逻辑页分页。 |

## 统一分页代码参考

`lib/theme/responsive-pager.ts` 是完整逻辑页分页的唯一几何工具。`tests/responsive-pager.test.ts` 覆盖其异常索引、零宽、半页阈值与连续宽度变化边界；`tests/schedule-responsive-pager.test.ts` 守护劳动模块对该工具的接入。
