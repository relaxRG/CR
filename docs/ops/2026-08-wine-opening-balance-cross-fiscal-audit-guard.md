# 葡萄酒独立期初：跨财年审计追溯与历史断层防护方案

## 目标与边界

供应商与酒款的初始累计分别表示系统启用前的历史阅读起点，不是同一笔余额，也不参加当月真实采购投影核对。本方案防止后补期初、跨财年调整或历史链接修复造成累计曲线断层、关闭月份被回写或审计无法追溯。

## 不可破坏规则

| 规则 | 系统要求 | 阻断条件 |
|---|---|---|
| 期初独立 | 供应商和酒款期初可不同，分别审计 | 禁止用差额自动调平 |
| 月度真实采购 | 月度统计仅来自采购流水 | 禁止把期初注入本月进货或成本 |
| 归档不可变 | 月结保存期初与审计副本 | 禁止直接覆盖关闭月份副本 |
| 更正追加 | 历史差错用更正记录解释 | 禁止物理删除审计或采购凭据 |
| 月份边界 | 一笔采购只属于一个业务月 | 禁止跨月移动而无恢复点 |

## 历史断层防护

管理员录入或修改期初时，系统生成包含操作者、原因、凭据摘要、修改前后金额、业务月、关联范围和关联归档 ID 的审计记录。若变更发生在已经产生月结归档之后，新的期初仅从当前开放月份生效；报表同时标注“历史期初已更正，关闭月份保留原始归档”。

跨财年时，系统在财年末生成只读审计锚点：当年各月真实采购、开放期初、关闭月份期初归档、待链接采购和未解决差异清单。新财年报表从该锚点延续，但不能重新计算或覆盖上财年归档。

## 追溯链

1. 管理员从供应商或酒款累计行进入“期初审计”。
2. 系统展示该对象所有期初创建、修改、删除和归档记录。
3. 选择任一审计记录，可查看修改原因、凭据摘要、影响起始月份和后续归档标识。
4. 对月度异常，先检查当月真实采购和待链接清单；只有确认属于系统启用前历史时才处理期初。
5. 对关闭月份，使用更正记录和后续开放月调整，不回写归档副本。

## 跨财年演练与放行

| 演练 | 预期结果 |
|---|---|
| 在新财年修改供应商期初 | 新记录被审计；上财年归档不变 |
| 酒款期初独立于供应商期初 | 无错误告警或自动调平 |
| 修复上一财年未链接采购 | 原月流水保留审计；当前读模型显示修复状态 |
| 恢复月结前状态 | 仅使用受控恢复点；恢复操作可追溯 |
| 审计导出 | 可按财年、对象、动作、月份导出完整记录 |

## 运营告警

对“关闭月份被写入”“无原因期初变更”“同一对象短期反复修改”“待链接采购跨财年未解决”发送告警。告警默认只读，不自动改金额；人工核实后以追加审计或受控恢复结束处理。

## 复核清单

- [ ] 每次期初修改均有原因和凭据摘要。
- [ ] 供应商、酒款两个期初视图未被错误要求相等。
- [ ] 本月采购与期初金额未混算。
- [ ] 已关闭月份的归档副本未被改写。
- [ ] 财年锚点已生成，待链接采购有责任人和处理期限。
