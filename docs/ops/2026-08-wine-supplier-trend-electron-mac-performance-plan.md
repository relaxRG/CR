# 葡萄酒供应商趋势组件：Electron / Mac App 性能压测与内存泄漏排查方案

## 目标

验证供应商趋势在真实桌面窗口缩放、柱状图/表格切换、月份切换和长时间驻留时保持响应、内存稳定和状态正确。所有压测使用脱敏或合成数据，不连接生产采购、期初或付款数据。

## 测试场景

| 场景 | 操作 | 关注指标 |
|---|---|---|
| 窗口缩放 | 400px 到 1600px 往返拖动 100 次 | 布局抖动、白屏、峰值 JS 堆、重渲染次数 |
| 图表/表格切换 | 同一月份切换 500 次 | 视图状态、订阅数、堆增长、切换耗时 |
| 大数据 | 6/50/500 供应商、36 个月趋势 | 首次渲染、筛选、滚动与 Tooltip 响应 |
| 高频月份切换 | 连续切换 24 个月并在中途取消 | 旧请求回写、内存残留、加载状态 |
| 长驻留 | 窗口打开 4 小时，每 5 分钟切换视图 | 堆曲线、监听器和定时器泄漏 |

## Electron 压测步骤

1. 使用 `--enable-precise-memory-info` 启动影子构建，并在 Performance 面板开启 JS CPU profiler。
2. 打开趋势组件，记录冷启动、首次数据提交和首次图表渲染时间。
3. 通过 Playwright 或 Electron 自动化脚本重复执行窗口缩放、切换、月份选择和供应商点击。
4. 在基线、100 次、500 次和卸载组件后分别采集 Chromium heap snapshot。
5. 在 DevTools 的 Event Listener Breakpoints 与 React Profiler 中检查未卸载订阅、`resize` 监听、定时器、Tooltip DOM 节点和数组缓存。

## Mac App 压测步骤

在 macOS 上分别覆盖全屏、半屏、窄窗口与 Retina 缩放。使用 Instruments 的 Allocations、Leaks、Time Profiler 和 Core Animation；记录窗口调整后的主线程峰值、图层数量与常驻内存。若组件运行在 React Native macOS 容器中，额外检查原生视图释放和 JS/原生桥引用。

## 验收阈值

| 项目 | 目标 |
|---|---|
| 500 次图表/表格切换后 JS 堆净增长 | 小于 5 MB |
| 100 次窗口缩放后常驻堆净增长 | 小于 3 MB |
| 50 供应商常规窗口首屏渲染 | 小于 300 ms |
| 单次视图切换 P95 | 小于 100 ms |
| 切换并返回原视图 | 月份、筛选、比较期和选中供应商保持不变 |
| 组件卸载后 | 无 `resize`、订阅、interval、tooltip 或图层残留 |

## 泄漏排查清单

- `useWindowDimensions` 外不得再注册未清理的 `resize` 监听。
- 比较模型必须 memoize，窗口宽度变化不得重新读取采购事实。
- 图表 Tooltip、动画和横向滚动引用必须在切换与卸载时释放。
- 避免将全部月份、供应商或点击闭包永久保存在全局状态。
- 比较请求采用 revision/generation ticket；旧月请求完成后不得回写新月视图。
- Heap snapshot 中若存在增长的 `WineSupplierTrendSwitcher`、数组或监听器链，先检查父级缓存和未取消的异步任务。

## 故障注入

模拟空数据、500 供应商、对比期零基数、连续 resize、网络延迟 5 秒、组件在请求中卸载、系统字体倍率 1.45。任何场景出现状态重置、金额口径变化、未释放监听器或堆持续上升，都不得通过桌面发布验收。
