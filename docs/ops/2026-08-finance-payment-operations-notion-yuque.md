# 财务与运营巡检手册：统一供货商付款与啤酒成本

> **适用模块：** 烈酒进销存（含“啤酒 / Beer”分类）、统一供货商付款、网络采购备用金、总月报付款汇总。  
> **不适用：** 将葡萄酒供应商并入烈酒供应商；以付款金额修改采购成本；按供应商名称自动匹配账务。

---

## 一、每日开店前巡检

### 目标

在付款金额不平、采购超核销、预付款异常、网络采购凭证缺失、啤酒成本混算或月报投影滞后影响经营数据前完成发现与分派。

### 执行清单

- [ ] 打开 Grafana「Cocktail R · 付款与啤酒成本完整性」大盘。
- [ ] 确认「付款金额不平（笔）」为 **0**。
- [ ] 确认「分类成本拆分差额」为 **0**。
- [ ] 确认不存在 `Critical` 未关闭告警。
- [ ] 检查网络采购待关联备用金的笔数与金额。
- [ ] 检查历史采购待确认分类金额占比；目标低于 **2%**。
- [ ] 确认月报投影 revision 延迟低于 **5 分钟**。
- [ ] 记录巡检时间、人员、未关闭工单和负责人。

> **重要：** 发现 Critical 后，不要通过重新录入付款、删除历史记录或直接修改采购金额来“消除告警”。先冻结受影响供应商的新核销，再按异常 Runbook 对账。

---

## 二、供货商统一付款的正常操作

1. 在烈酒采购档案或总月报「烈酒付款汇总」中找到供货商。
2. 核对供应商的统一采购、已付、待付金额，以及“其中啤酒 / Beer”和“非啤酒烈酒”的构成。
3. 点击 **录入统一付款**，填写真实付款金额、日期、方式和凭证。
4. 在按行拆分区，将金额分配到具体采购行；啤酒与其它烈酒可以在同一付款单内核销。
5. 核对底部：`本次付款 = 已分配 + 未分配`。
6. 未分配金额只能继续分配、保存为预付款或保存草稿；不能直接显示为已核销。
7. 提交后复核付款卡：供应商总已付/待付更新，啤酒与其它烈酒构成更新；采购成本和库存成本不应因付款而变化。

## 三、异常处理速查

| 告警 | 含义 | 立即动作 | 正确修复 |
|---|---|---|---|
| PAY-001 付款金额不平 | 付款金额不等于分配金额加预付款 | 冻结该付款的后续核销 | 补足明确预付款或冲销错误分配；运行守恒验证 |
| PAY-002 采购超核销 | 已核销金额超过采购金额 | 停止该供货商新分配 | 冲销多余 allocation，不删除历史 |
| PAY-003 预付款为负 | 同一 credit 被重复抵扣或并发写入 | 冻结预付款抵扣 | 核对并发/operationId，冲销多余抵扣 |
| PAY-006 网络采购无凭证 | 备用金付款缺少凭证关联 | 保持“待关联” | 关联正确备用金，或改为直接付款并留说明 |
| BEER-002 分类拆分不守恒 | 啤酒+烈酒+待确认不等于总采购 | 隔离该月分类月报投影 | 导出差异采购行，修复快照后重建投影 |
| BEER-003 啤酒成本混入烈酒 | beer 行进入非啤酒烈酒成本 | 隔离错误卡片 | 修正分类投影/快照；不得修改采购金额 |
| BEER-005 月结历史被改分类 | 已发布月份被普通编辑影响 | 停止普通编辑 | 发起月结调整，说明原因并审批 |
| BEER-006 投影滞后 | 报表 revision 落后事实 | 显示“刷新中” | 刷新权威投影，排查旧请求回写 |

## 四、每周对账

- [ ] 抽样至少 5 个同时供应啤酒和其它烈酒的供货商。
- [ ] 核对供货商统一应付与各采购行分配总额。
- [ ] 核对啤酒 / Beer 与非啤酒烈酒采购成本、已付和待付构成。
- [ ] 核对跨账期付款：付款月是现金流，采购月是成本，不得产生第二笔成本。
- [ ] 核对预付款来源、可用余额和抵扣目标；不允许跨供货商使用。
- [ ] 核对已付网络采购的备用金或直接付款凭证。
- [ ] 检查待确认分类清单是否有负责人和完成日期。

---

## 五、月结前强制检查

月结仅可在以下条件全部满足时执行：

- [ ] 付款守恒差额为 0。
- [ ] 采购超核销行数为 0。
- [ ] 啤酒/烈酒分类拆分差额为 0。
- [ ] 月报投影无 revision 延迟。
- [ ] 本月无未授权的历史重分类。
- [ ] 所有 Critical 与 High 告警已关闭，或拥有审批的明确豁免。

已月结月份发生错误时，只能通过**冲销、调整或授权重分类**修复，禁止直接编辑采购金额、删除付款或删除分配记录。

---

## 六、告警关闭标准

只有同时满足下列条件，才可关闭 Critical/High：

1. 已关联工单、处理原因、处理人和审批人（如需要）。
2. 修复使用调整、冲销或受控重分类；未物理删除账务历史。
3. 付款守恒、采购未超核销、分类拆分守恒查询均为零差额。
4. 月报投影已刷新到最新 revision。
5. 告警经历至少一次后续采集周期后保持 `resolved`。
