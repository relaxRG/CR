# 葡萄酒供应商趋势：低性能移动设备 FPS、内存与渲染降级方案

## 性能目标

趋势组件在低端 Android 和旧 iPhone 上必须维持可交互体验：常规数据量下滚动与点击目标为 55–60 FPS；重数据量下允许降至 45 FPS，但不能连续掉帧、触控失效或造成内存持续增长。

| 数据规模 | 供应商数 | 月份数 | 默认渲染 | 目标 |
|---|---:|---:|---|---|
| 小 | ≤ 12 | ≤ 12 | 原生柱状图 / 普通表格 | 首帧 < 200ms |
| 中 | 13–60 | ≤ 24 | 可滚动柱状图 + 虚拟化表格 | 交互 P95 < 100ms |
| 大 | > 60 或 > 24 月 | 任意 | Canvas 柱层 + 虚拟列表 | 60/45 FPS 降级阈值 |

## 分析方法

在真实 Android 低端设备、iPhone 旧机型与 iPad 分屏上采集：JS FPS、UI FPS、JS 堆、原生堆、帧耗时 P95、首次渲染、图表/表格切换、月份切换和连续滚动。使用 React Profiler 标记比较模型、柱体绘制和表格行渲染；使用 Flipper/Android Studio Profiler/Xcode Instruments 检查桥调用、图片、闭包和列表行滞留。

## 虚拟滚动方案

表格模式必须使用 `FlashList` 或 `FlatList`，设置稳定 `keyExtractor`、固定/可预测行高、`initialNumToRender`、`windowSize` 和 `getItemLayout`。动态字体超过 1.15 时关闭固定 `getItemLayout`，改用测量缓存，避免行高错误。供应商名和金额不应以匿名行组件重复创建；行组件使用 `React.memo`，比较模型用 `useMemo` 仅依赖月份、筛选和真实读模型 revision。

## Canvas 降级方案

当柱数超过 60 或性能采样连续 3 秒低于 45 FPS 时，柱体层改用 `react-native-skia` 或原生 Canvas 绘制；文字、选择和无障碍信息仍保留为可访问覆盖层。Canvas 只接收归一化的只读数组，不持有采购事实；点击坐标根据缩放比例映射到供应商 ID。降级后仍必须可切换表格，且表格金额与 Canvas Tooltip 同源。

## 内存防护

- 禁止为每月、每供应商常驻保留完整采购明细；趋势只保存聚合行和当前下钻数据。
- 图表切换时释放 Tooltip、动画回调、横向滚动监听和 Canvas 资源。
- 使用 revision ticket 取消过期比较请求；组件卸载后不得提交状态。
- 每次筛选变化前清除旧的离屏选择映射，避免供应商数组被闭包保留。
- 性能监控只上传聚合指标，不上传供应商、采购或金额明细。

## 压测与验收

运行 10 分钟连续月份切换、500 次图表/表格切换、100 次窗口/方向变化、500 供应商/36 个月数据和 4 小时驻留。验收要求：JS 堆净增长 < 8MB、原生堆无单调增长、组件卸载后无监听器、低端机滚动 P95 帧时 < 22ms、触控点击成功率 100%。若未达到阈值，先启用虚拟列表，再启用 Canvas；不得通过缩小字体、减少审计字段或改变金额口径来掩盖性能问题。
