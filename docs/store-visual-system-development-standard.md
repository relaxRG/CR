# cocktail R 门店统一视觉系统前端开发规范

> **适用范围**：门店模块中的报表、员工、备用金、库存与店铺，以及后续新增的门店二级页面。
>
> **规范目标**：所有页面共享同一套视觉层级、图标频次、基础颜色角色与 iPhone / iPad / Mac 信息密度；但**不得把员工页面的业务颜色机械套用到报表、库存或其他领域**。

## 1. 设计原则

本规范综合采用 Apple 的布局、颜色、SF Symbols 和可调整窗口建议：通过分组、留白、对齐和轻量分隔建立层级；颜色与图标只承担明确语义；重要状态不得只依赖颜色表达。[1] [2] [3] iCost 的分类颜色、日历与统计视图说明了一个补充原则：同一分类在列表、图例和统计中应维持一致，但普通数据不应被染成“状态色”。[4]

门店界面以**中性正文为底、有限语义色为强调、一次性分类图标为识别、可扩展密度为跨端策略**。不以大面积纯黑粗字、每行重复图标、强边框、装饰性颜色或浮动大按钮制造层级。

| 必须做到 | 禁止做法 |
|---|---|
| 先判断信息是否需要用户行动，再决定是否使用颜色 | 因金额为正或负，就自动使用绿色或红色 |
| 将颜色角色与领域解释分开维护 | 把“蓝=前厅”写成全局规则，并用于库存或报表 |
| 图标只出现于分组、状态或操作入口 | 在长列表的每个姓名、每个金额、每个台账格重复使用图标 |
| 以信息密度随屏宽改变，不改变业务顺序 | 在 iPhone 强塞桌面五列，或在 Mac 无限放大手机卡片 |
| 用文字、图标、颜色三者至少两项表达异常 | 只用红色、绿色或图标表达重要状态 |

## 2. 两层颜色模型

### 2.1 第一层：全门店共用的基础颜色角色

基础角色表示**展示意图**，不直接表示某个业务事实。组件只接收 `StoreVisualTone`，不应在页面自行定义新颜色池。

| 基础角色 | 令牌 | 视觉用途 | 不能表示什么 |
|---|---|---|---|
| 中性 | `neutral` | 常规正文、普通金额、普通台账字段、历史值 | 不能表达完成、警告或异常 |
| 主色 | `primary` | 当前页签、当前筛选、唯一主要操作 | 不能默认表示收入、库存充足或成功 |
| 正向 | `positive` | 已确认完成、明确正向结果、成功入账 | 不能给所有正数金额上色 |
| 关注 | `attention` | 待确认、待补充、临近截止、需注意变化 | 不能作为普通费用、普通加班或普通库存的默认色 |
| 辅助分类 | `accent` | 图表第二分类、分组色点、关联项 | 不能表达警告、失败或主操作 |
| 异常 | `danger` | 差额、失败、冲突、违规数据、真实风险 | 不能用作普通分类色或装饰色 |
| 弱化 | `muted` | 零值、无数据、历史、辅助说明、禁用态 | 不能代替可点击主操作 |

实现位置：`lib/theme/store-visual-system.ts` 中的 `storeTone()`、`storeToneSurface()` 与 `STORE_CATEGORY_TONES`。

> `STORE_CATEGORY_TONES` 不含 `danger`。普通菜品、库存分类、费用科目或统计系列不得因为色序轮换而呈现红色，以免被误读为异常。

### 2.2 第二层：领域颜色映射

每个模块必须按照 `STORE_DOMAIN_COLOR_RULES` 解释基础颜色。新增字段或视图时，先在该映射中确定语义，再调用共享组件。以下内容为唯一认可的默认映射。

#### 报表

| 报表信息 | 默认角色 | 说明 |
|---|---|---|
| 营业收入、支出、手续费、菜品大类金额、历史同比 | `neutral` | 金额本身不是状态，不按正负自动着色 |
| 当前报表页签、筛选、主导入/导出动作 | `primary` | 每个工具栏最多一个强调主操作 |
| 正向净利润、已归档、明确达标趋势 | `positive` | 必须同时显示“净利润为正”“已归档”或趋势符号 |
| 待补充数据、未核对期间、需复查的环比变化 | `attention` | 不用于普通成本和手续费 |
| 菜品大类、收入构成、图例第二分类 | `accent` | 仅用于图表、色点与分组标题，不覆盖整行文字 |
| 负净利润、金额校验差额、导入失败、财务异常 | `danger` | 需要明确文字说明异常原因 |

**报表的关键结论**：总收入、总支出、手续费和各菜品大类默认使用中性文字；只有净利润、趋势、异常或操作状态才用语义色。这样避免“所有数字都绿色”或“所有成本都红色”的误读。

#### 员工

| 员工信息 | 默认角色 | 说明 |
|---|---|---|
| 姓名、底薪、实发、已预支和普通薪资字段 | `neutral` | 不使用纯黑粗字压满列表 |
| 前厅分类、当前操作、待发薪资 | `primary` | 前厅图标只出现在分组标题一次 |
| 后厨分类、已发薪资、已完成核对/归档 | `positive` | 后厨色只用于分组识别与完成状态 |
| 加班、到期调休、待确认考勤 | `attention` | 保留文字原因，不单独依赖琥珀色 |
| 补贴、绩效、预支关联 | `accent` | 不代表错误或收入 |
| 薪资差额、扣款异常、同步冲突 | `danger` | 需要可进入核对/修正入口 |

#### 备用金

| 备用金信息 | 默认角色 | 说明 |
|---|---|---|
| 普通支出、期初/期末余额、账本金额、历史记录 | `neutral` | 支出不是自动红色，收入不是自动绿色 |
| 当前账本/日历/统计视图、手工录入 | `primary` | “新增记录”属于顶部上下文操作栏 |
| 确认入账、正常收入、月结完成 | `positive` | 应显示“已入账”“已月结”等文字 |
| 待分类、待核对、临近月结、缺少凭证 | `attention` | 不等价于出错 |
| 备用金转入、内部资金调拨 | `accent` | 不用于普通收入 |
| 账实不符、负余额、重复导入、明确错误记录 | `danger` | 必须提供修复或核对路径 |

#### 库存

| 库存信息 | 默认角色 | 说明 |
|---|---|---|
| 库存量、单位成本、进货成本、消耗、期初/期末、普通台账金额 | `neutral` | Excel 台账默认中性，便于高密度核对 |
| 当前分类、当前工作台、采购录入、可执行主操作 | `primary` | 只强调当前选择或当前操作 |
| 已月结、盘点确认、导入成功、归档完成 | `positive` | 不能用来表示库存量“充足” |
| 待盘点、待补全分类、待确认月结草稿 | `attention` | **不恢复已删除的库存预警功能** |
| 统计图、分类分组色点、图例第二色 | `accent` | 不进入每个库存行或每个金额 |
| 损耗、盘点差异、导入冲突、负库存数据 | `danger` | 必须有异常文字和处理入口 |

**库存的关键结论**：库存和成本不是绿、红、蓝的业务事实；它们默认中性。只有盘点差异、损耗、负库存、导入冲突才是异常。库存分类的颜色只用于分组行、图例或图表，避免 Excel 台账成为彩色表格。

#### 店铺

| 店铺信息 | 默认角色 | 说明 |
|---|---|---|
| 杯具、餐具、日用品、设备的普通数量、成本和台账字段 | `neutral` | 普通资产数据不带状态色 |
| 当前分类、登记/录入主操作 | `primary` | 保持与库存工作台一致 |
| 维护完成、折旧确认、盘点完成、归档完成 | `positive` | 完成状态必须具备文字标签 |
| 待维护、待盘点、待补资料 | `attention` | 不代表资产异常 |
| 图表和分类分组辅助色 | `accent` | 仅用于结构识别 |
| 损耗、维修异常、盘点差异、数据冲突 | `danger` | 提供核对或修复入口 |

## 3. 字体与图标规范

### 3.1 文本层级

| 层级 | 令牌 | 字重 | 使用场景 |
|---|---|---|---|
| 页面标题 | `STORE_TEXT.pageTitle` | 600 | 页面名称、弹窗标题 |
| 分组标题 | `STORE_TEXT.sectionTitle` | 600 | 前厅、后厨、库存分类、报表区块 |
| 行标题 | `STORE_TEXT.rowTitle` | 600 | 员工姓名、账本名称、资产名称 |
| 正文 | `STORE_TEXT.body` | 500 | 普通金额、字段名、可读数据 |
| 辅助说明 | `STORE_TEXT.supporting` | 400 | 日期、单位、英文别名、来源、说明 |
| 关键指标 | `STORE_TEXT.metric` / `metricLarge` | 600 | 经过筛选的主金额或总览指标 |

日常标题、姓名、金额、台账行不得使用 700、800、900。唯一例外是小型异常徽标中需要在极小字号下维持识别度的短文字；它必须同时受限于 10pt 以下且不用于常规内容。

### 3.2 图标频次与尺寸

| 场景 | 上限 | 规则 |
|---|---:|---|
| 分类或分组标题 | 14pt | 每个分组仅一次；优先线性 SF Symbol 或统一系统图标 |
| 工具栏操作 | 16pt | 与文字并列；一个工具栏只有一个强调操作 |
| 行内展开细节 | 10–12pt | 只出现在展开分区标题，不能每列重复 |
| 导航 | 18pt | 仅顶级导航、底部导航或明确入口 |
| 常规界面最大值 | 18pt | 不得出现大号装饰图标或漂浮圆形 `+` |

## 4. 布局、控件和跨端密度

### 4.1 固定尺寸

| 元素 | 规则 |
|---|---|
| 门店二级分段栏 | 40pt，高度统一，文字为主，选中态仅使用细下划线和主色 |
| 上下文操作 | 36pt，文字 + 16pt 图标；不使用屏幕绝对定位的悬浮操作 |
| 分组标题 | 最小 30pt，14pt 图标或色点 + 标题 + 可选数量 |
| 页面水平留白 | 16pt；不可因页面不同而随意改成 8pt、24pt |
| 卡片圆角 | 12–14pt；用留白和轻边线分组，不叠加重阴影和重描边 |

### 4.2 三端适配矩阵

| 能力 | iPhone：≤599pt | iPad：600–1023pt | Mac：≥1024pt |
|---|---|---|---|
| 总览指标 | 2×2；关键行展示 3 个指标 | 4 列总览；5 个关键指标 | 4 列总览；5 个稳定指标，内容最大宽度 1240pt |
| 账本/员工行 | 姓名 + 状态 + 主金额；其余点击展开 | 姓名、主金额与 3–5 项关键字段 | 稳定多列，但不通过放大字体填满窗口 |
| 二级导航 | 横向可滚动，40pt | 尽量完整显示，仍允许横向滚动 | 同样的顺序与选择逻辑，不改为另一套导航 |
| 操作栏 | 主操作 + 少量高频动作，其他折叠/滚动 | 显示关键操作组 | 紧凑工具栏，可提供悬停提示与快捷操作 |
| 表格 | 固定关键列 + 横向滚动；点击行可展开 | 扩展可视列，但保持横向滚动能力 | 最大内容宽度内稳定表列，不能让表格无限拉伸 |
| 日历 | 色点、汇总和点击详情；不塞密集文本 | 月历与日明细可并列 | 月历、筛选和详情稳定并列 |

## 5. 共享组件与接入要求

新增或改造门店页面必须优先使用以下组件和令牌。

| 目标 | 必用实现 |
|---|---|
| 二级页签 | `StoreSegmentedTabs` |
| 分组标题 | `StoreSectionHeader` |
| 总览指标 | `StoreMetric` |
| 上下文操作 | `StoreToolbarAction` |
| 三端内容壳 | `StoreContentShell` / `useStoreDensity()` |
| 色彩和字重 | `storeTone()`、`storeToneSurface()`、`STORE_TEXT`、`STORE_VISUAL_SYSTEM` |
| 领域色彩决策 | `STORE_DOMAIN_COLOR_RULES` |

页面不得复制上述组件后再局部改写。若共享组件无法满足需求，应先扩展共享组件及其测试，而不是新建第二套视觉规范。

### 示例：库存月结操作

```tsx
<StoreToolbarAction
  label="月结"
  icon="lock.fill"
  tone="primary"
  emphasis
  colors={colors}
  accessibilityLabel={`确认 ${month} 库存月结`}
  accessibilityHint="确认后锁定本月库存台账，仍可通过受控修正流程处理差异"
  onPress={handleMonthClose}
/>
```

### 示例：报表净利润

```tsx
const tone = netProfit < 0 ? "danger" : netProfit > 0 ? "positive" : "neutral";
<StoreMetric
  label="本月净利润"
  value={formatStoreMoney(netProfit)}
  tone={tone}
  icon="chart.line.uptrend.xyaxis"
  colors={colors}
/>
```

该示例只允许用于**净利润这类确实需要表达正负结果的指标**。总营业收入、总支出、手续费和普通库存成本不能照搬这个规则。

## 6. 可访问性和测试门禁

所有操作必须提供中文 `accessibilityLabel`；有副作用、范围或不可逆性的操作必须附加 `accessibilityHint`。例如薪资重算需要明确“仅重建所选月草稿薪资，不修改其他月份或已确认发薪数据”。

提交前必须运行：

```bash
pnpm check
pnpm test -- --reporter=dot
git diff --check
pnpm test:h5:store-segmented-nav
pnpm test:h5:global-month-stress
```

`tests/store-visual-system-policy.test.ts` 是门店视觉系统门禁。它至少检查三端断点、40pt 分段栏、36pt 工具栏、图标大小、日常字重上限、分类色序中不出现异常红，以及报表/库存的领域色彩映射。新增领域色彩或共享组件时，必须同步扩展此测试。

## 7. 开发评审清单

在合并前，开发者和评审者应确认以下问题均为“是”。

1. 该颜色表达的是状态、选择、完成、关注或异常，而不是随意装饰吗？
2. 该颜色在所属领域中符合 `STORE_DOMAIN_COLOR_RULES` 吗？
3. 普通收入、支出、成本、库存量、台账金额是否仍然保持中性？
4. 该图标是否只出现一次于分组、状态或操作入口，而不是重复出现在每行？
5. iPhone 是否保留了可读的关键三项，而非把桌面字段强塞进一行？
6. iPad 是否提升了可视信息量但没有改变阅读顺序？
7. Mac 是否限制内容宽度、保持稳定列，而不是放大移动端卡片？
8. 该操作是否有中文无障碍名称和必要的影响说明？
9. 共享组件是否已复用；若未复用，原因是否已在共享层解决？
10. 类型检查、全量测试、H5 多尺寸和月份压力回归是否通过？

## 附录 A：色彩如何增加、选择与展示

颜色不是固定配额，也不是只允许少数几种。新增颜色时必须先声明其属于哪一类用途：**领域分类、状态反馈、数据编码、操作强调或装饰品牌**。同一颜色不得跨类别承担相反含义。Apple 的颜色指南明确要求避免同色多义，并建议系统或自定义颜色同时覆盖浅色、深色和增强对比度；颜色不能作为关键信息的唯一载体。[1]

| 使用类别 | 允许增加颜色的条件 | 推荐展示位置 | 禁止展示位置 |
|---|---|---|---|
| 领域分类 | 用户需要在多个稳定类别中快速辨识；类别及颜色可长期保存 | 分组标题色点、分类图标背景、图例、图表系列、日历色点 | 每条普通台账行的整行底色、每个金额文本 |
| 状态反馈 | 状态可操作、可改变，且用户需要立即识别 | 状态标签、异常提示、确认结果、受控图标 | 普通金额、普通分类或纯装饰背景 |
| 数据编码 | 图表同时展示三种以上独立系列，且存在图例 | 柱线、饼图扇区、图例和对应分组色点 | 无图例的密集表格、阅读型正文 |
| 操作强调 | 当前页面只存在一个真正的主要动作 | 主要按钮背景、当前页签、选中态 | 多个相邻按钮同时高亮、普通文字 |
| 品牌装饰 | 内容区域单色且品牌色能提升连续性 | 页面级小面积背景、顶部细强调线 | 大面积卡片、账本/库存的高密度数据区 |

新增颜色的评审顺序为：先复用现有基础角色；若不能表达，再新增为“领域分类色”或“图表色”；只有在需要可操作的异常/完成状态时才新增状态色。新增项必须定义浅色、深色、高对比度三组变体，定义对应图标或文字描述，并在 `STORE_DOMAIN_COLOR_RULES` 和测试门禁中登记。

Apple 的 SF Symbols 建议可以通过单色、层级、调色板和多彩渲染区分图标层级；其中层级渲染适合使用单一颜色和不同透明度表达主次，调色板渲染适合确实需要两种以上语义层的图标。工具栏和列表优先使用轮廓符号，选中态才考虑填充符号。[3] iCost 的公开更新记录显示其支持分类图标与自定义配色、分类统计图标跟随饼图或使用自定义色系，并持续维护 iPad 与 Mac 的具体兼容问题；这支持“分类可扩展、状态不滥用、跨端要逐项验证”的策略。[4]

## 附录 B：Apple / iCost 研究摘录与本项目决策

| 研究发现 | cocktail R 决策 |
|---|---|
| Apple：系统颜色以语义而非固定数值定义，并随外观和辅助功能适配。[1] | 主题色不在业务页面硬编码；`storeTone()` 统一从当前主题读取。 |
| Apple：主/次/第三层背景和主/次/第三层文本用来表达层级。[1] | 先用表面、留白、分隔线、`STORE_TEXT` 区分层级，颜色只负责额外语义。 |
| Apple：颜色不应成为状态或交互的唯一表达。[1] | 所有异常、完成、待处理状态都要求颜色 + 文字或图标。 |
| Apple：SF Symbols 的轮廓、填充、层级和调色板模式对应不同强调强度。[3] | 分组/工具栏以小号线性图标为默认；选中页签或高优先级状态才使用填充或双层颜色。 |
| Apple：布局在窗口调整、设备切换时应保持熟悉结构，只在不再容纳时转紧凑视图。[2] | 五大模块统一顺序；iPhone 减少可见指标、iPad 扩展列、Mac 限制内容宽度而不放大卡片。 |
| iCost：分类图标与统计颜色可跟随图表或使用自定义配色，并维护 iPad/Mac 适配。[4] | 用户可管理的分类使用稳定分类色；统计图、图例、分组标题共享同色，但危险状态色不参与普通分类轮换。 |

## 附录 C：门店可扩展分类调色板

分类颜色并非限制为五种。门店统一主题提供九个可轮换的分类槽位：`primary`、`categoryTeal`、`aiAccent`、`categoryIndigo`、`categoryCyan`、`categoryMint`、`categoryAmber`、`categoryPink`、`categoryCoral`。它们仅用于**用户可管理的分类、统计图系列、图例、分组色点和分类图标背景**；不会替换 `success`、`warning`、`error` 的状态语义，也不用于普通台账金额。

当一个图表或分类列表超过九类时，不得直接增加一串相近新颜色。应首先采用以下策略：合并“其他”、按用户排序只突出前九类、使用可点击图例筛选、通过图标/标签形状补充识别，或分面展示。只有当第十个类别也是稳定且高频的业务实体时，才可以新增第十种主题分类色；新增前必须同时提供浅色、深色与增强对比度版本，并补充主题令牌、`STORE_CATEGORY_COLOR_KEYS`、领域映射说明和自动化测试。

| 颜色槽位 | 推荐第一用途 | 推荐展示方式 |
|---|---|---|
| `primary` | 当前选中分类或第一图表系列 | 细下划线、色点、线条、图例 |
| `categoryTeal` | 第二稳定分类 | 图表系列、分组标题图标 |
| `aiAccent` | 关联/自定义分类 | 图例与轻量图标背景 |
| `categoryIndigo` | 第四稳定分类 | 图表系列与日历色点 |
| `categoryCyan` | 第五稳定分类 | 图表系列与分组色点 |
| `categoryMint` | 第六稳定分类 | 图表系列与分组色点 |
| `categoryAmber` | 第七稳定分类；不表示待处理 | 图表系列与分类图标背景 |
| `categoryPink` | 第八稳定分类 | 图表系列与分类图标背景 |
| `categoryCoral` | 第九稳定分类；不表示错误 | 图表系列与分类图标背景 |

> `warning` 和 `error` 永远是状态色；即使它们在视觉上同样是橙/红，也不能进入普通分类轮换。分类色的含义来自图例和类别名称，状态色的含义来自状态文字和操作路径。
