# 库存与店铺工作台开发规范

**适用范围**：库存六类（烈酒、葡萄酒、水果、食材、啤酒、冰块）与店铺四类（杯具、餐具、日用品、设备）。

**目标**：确保十类工作区在移动端保持一致的分类切换、月份状态、嵌入布局、操作栏、同步语义和回归保护；禁止通过保留第二套旧状态或兼容UI来掩盖问题。

## 1. 工作台架构

十类分类统一由 `components/store/inventory.tsx` 管理外层分类分段、月份浏览器和工作区装配。分类内部页面只负责本分类原有业务页签与数据操作，不能再次创建同层级的分类导航或月份导航。

| 层级 | 单一职责 | 禁止事项 |
|---|---|---|
| 主导航 | 报表、员工、备用金、库存、店铺 | 在子页面复制主导航 |
| 分类分段 | 库存六类或店铺四类切换 | 通过入口卡片再跳转到第二层管理页 |
| 月份浏览器 | 当前工作台的唯一月份状态与边界 | 每个分类另存可写月份副本；无限翻月 |
| 分类页面 | 总览、台账、进货、分析、损耗、折旧等原有业务页签 | 重新实现外层分类/月度状态 |

> 同一个工作台中的分类切换不得重置月份。进入详情、返回工作台或同步完成后，月份必须经统一边界函数校验。

## 2. 嵌入页面与安全区

库存、店铺工作台已提供顶部主导航、分类分段和月份导航。所有可嵌入的分类页面必须声明 `embedded?: boolean`，并使用以下容器规则：

```tsx
<ScreenContainer edges={embedded ? [] : undefined}>
```

独立路由保留系统安全区与返回导航；嵌入工作台时必须移除重复安全区、返回导航、页面标题和重复月份导航。禁止用空白 `View`、`flex: 1` 或大 `minHeight` 补偿顶部区域。

| 文件类型 | 标准 |
|---|---|
| 通用分类页面 | 通过 `BaseInventoryScreen` 自动继承嵌入安全区规则 |
| 独立实现页面 | 烈酒、葡萄酒、食材、设备必须显式使用 `embedded` 与条件 `edges` |
| 工作台外层 | 只保留分类分段、统一月份和当前业务页签内容 |

## 3. 移动端布局与横向滚动

横向内容只能在自身容器横向滚动，页面根容器不得横向溢出。工具栏、分类标签、业务页签和Excel台账必须是相互独立的横向滚动区域。

```tsx
<ScrollView horizontal showsHorizontalScrollIndicator={false}>
  <TouchableOpacity style={{ flexShrink: 0, minHeight: 44 }}>
    <Text numberOfLines={1}>操作名称</Text>
  </TouchableOpacity>
</ScrollView>
```

操作栏必须保持同一行，不得因窄屏折为多行。按钮最小触控高度为44pt，`flexShrink: 0`，文字单行显示；父容器不得使用会裁切按钮内容的固定高度或 `overflow: hidden`。月份导航只能使用内容高度与明确的8–12pt间距，禁止生成空白撑高区。

## 4. 烈酒库存双视图

烈酒库存管理必须同时保留两个独立视图：

| 视图 | 用途 | 规则 |
|---|---|---|
| 移动概览 | 商品名称、期末库存、期末成本的快速浏览 | 点击名称打开详情卡片；仅对可见列提供调整 |
| Excel台账 | 全量进销存核对 | 14列固定顺序、横向滑动、最右集团列、动态合计 |

两套视图使用同一份月度台账数据和相同月份状态，但视图偏好仅本地持久化，不同步为业务数据。禁止重新引入按屏幕宽度自动删除其中一个视图的逻辑。

Excel台账固定列顺序为：

```text
序号 → 商品名称 → 参考价 → 期初库存量 → 期初单价 → 期初成本 →
进货数量 → 进货成本 → 期末库存量 → 期末单位成本 → 期末成本 →
消耗瓶数 → 消耗成本 → 集团
```

商品名称支持中文/英文、名称多选、未匹配筛选、关键词和排序；数值列支持升降序与数值区间。筛选采用交集逻辑，合计行仅汇总当前可见记录。排序与筛选必须通过纯展示引擎处理副本，不能改变导入记录、库存账务、同步数据或Excel导出顺序。

## 5. 进销存分类生命周期

分类操作必须由单一生命周期引擎执行。分类新增、重命名、上下排序、内容迁移和删除不得散落在多个页面状态中。

| 操作 | 强制语义 |
|---|---|
| 新增 | 创建可排序分类，不改变已有商品 |
| 重命名 | 同步更新商品与采购记录的显示分类，历史账务不丢失 |
| 上移/下移 | 只交换相邻分类顺序，并持久化排序字段 |
| 删除空分类 | 可执行最终删除 |
| 删除有内容分类 | 必须先原子迁移全部商品至目标分类或“未分类” |
| 未分类 | 系统兜底分类，不可删除 |

禁止保留绕过内容检查的普通删除接口。删除流程必须先判断内容数量，再迁移或置为未分类，最后删除空分类，避免孤儿商品和同步中间态。

## 6. 废弃字段与历史数据

删除字段必须覆盖：类型定义、状态接口、表单、导入、导出、计算、展示、测试和持久化加载。旧字段不得继续参与运行时业务计算。

`alertThreshold` 已从库存业务模型删除。历史本地数据读取时由专用清理器剥离该字段；清理器与测试是删除保护，不是旧预警功能的兼容层。严禁重新在表单、导入模板、状态模型或同步映射中写入该字段。

烈酒台账中的消耗瓶数和消耗成本必须严格分离。Excel解析、预览、月度写入、历史归一化和展示必须使用独立字段；不得将成本值写入数量字段或以混合字段兼容旧逻辑。

## 7. 状态、同步与性能

所有工作台显示状态分为两类：

| 类型 | 示例 | 是否同步 |
|---|---|---|
| 业务状态 | 商品、分类、进货、盘点、损耗、月度台账 | 是，受工作台数据边界保护 |
| 展示偏好 | 视图模式、中/EN显示、排序、筛选、折叠状态 | 否，仅本机持久化 |

分类或月份切换时只挂载当前分类业务面板。耗时汇总、分析和大列表渲染必须只基于当前分类与当前月份；不得预先挂载十类页面。批量导入和盘点应按存储键合并写入，避免逐条触发同步风暴。

## 8. 必须执行的验证

每次修改库存或店铺工作台，提交前必须执行：

```bash
pnpm check
pnpm test
pnpm test:h5:store-segmented-nav
```

H5回归必须覆盖375、390、430pt，并逐一验证：库存六类、店铺四类、根级无横向溢出、分类切换、统一月份保持、快速选月、无旧中间跳转入口。

若修改烈酒台账、分类生命周期或Excel映射，还必须覆盖：完整14列、最右集团、动态合计、多条件交集、导入导出不变、消耗瓶数与成本分离、非空分类删除拦截。

## 9. 代码评审清单

提交前必须逐项确认：

- [ ] 嵌入页面使用 `edges={embedded ? [] : undefined}`。
- [ ] 横向工具栏和标签栏独立滚动，按钮不压缩且触控高度不少于44pt。
- [ ] 没有新增空白撑高容器、重复标题或重复月份导航。
- [ ] 没有新增第二套月份、分类、库存或同步可写状态。
- [ ] 删除字段已从模型、表单、导入导出、计算、展示和持久化路径清除。
- [ ] 历史清理器仅负责剥离旧字段，测试覆盖其数据保留边界。
- [ ] 排序筛选仅调整可见数据副本，不改写业务记录。
- [ ] `pnpm check`、`pnpm test`和H5三尺寸回归均通过。

## 10. 责任边界

新增功能应优先复用：`BoundedMonthNavigator`、`BaseInventoryScreen`、库存展示引擎、分类生命周期引擎和既有H5回归框架。若确实需要新增状态或页面容器，必须先说明为什么现有单一状态源无法覆盖，并同时增加防回归测试。

本规范由库存工作台重构沉淀，后续涉及多分类、月度台账、移动端横向操作栏或嵌入式工作区的改动均应遵守。
