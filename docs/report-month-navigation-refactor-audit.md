# 统一报表月份导航重构审计

## 改造目标

将**总月报、经营分析、账户**的月份选择统一为受限业务月份导航。三个页面共享用户已选月份；每页仍独立判断是否存在该月数据。页面无数据时显示该页面的空状态，不能切换至别的月份，更不能改写其他页面的月份。

## 受影响逻辑与引擎

| 范围 | 变更 | 说明 |
|---|---|---|
| `lib/reporting/month-navigation.ts` | 新增纯月份边界引擎 | 统一 `YYYY-MM`、`YYYY/MM`、日期和中文月份；由总月报、经营分析、账户、收入、备用金、薪资单月份并集计算边界 |
| `hooks/use-report-month-navigation.ts` | 新增共享状态 Hook | 使用 `store.report.active-month.v1` 持久化唯一业务月；路由 `month` 参数优先；仅超出并集边界时钳制 |
| `components/months/BoundedBusinessMonthNavigator.tsx` | 新增通用导航组件 | 复用库存的前后切换、居中选择、年份切换与月份网格交互，去除库存专属文案 |
| `app/monthly-summary.tsx` | 接入共享月份 | 删除固定最近 12 个月的 `MonthSelector` 与本地 `selectedMonth`；月结、薪资、供应商、库存汇总仍读取同一个业务月 |
| `components/store/analytics.tsx` | 月模式接入共享月份 | 删除固定最近 24 个月 `MonthPicker` 与本地月份状态；日、年、自定义时间段保持独立逻辑 |
| `components/store/accounts.tsx` | 接入共享月份 | 删除固定最近 12 个月 `MonthSelector` 与本地月份状态；无账户余额仍停留所选月并显示原有“尚未录入本月余额” |
| `app/(tabs)/store.tsx` | 跨路由月份保持 | 进入独立总月报路由时携带 `month` 参数；为报表子页签新增稳定测试标识 |
| `scripts/h5-schedule-correction-e2e.mjs` | 扩展移动端回归 | 六种宽度验证三页相同月份文案、导航存在与根级无横向溢出；完成后关闭专用测试页 |

## 删除的旧代码和冲突路径

| 删除项 | 原问题 | 当前替代 |
|---|---|---|
| 总月报 `MonthSelector` | 固定向前 12 个月，未按业务数据限制 | `BoundedBusinessMonthNavigator` + 共享边界 |
| 账户 `MonthSelector` | 固定向前 12 个月，账户页进入时独立默认当前月 | 同一导航组件 + 共享月份 Hook |
| 经营分析 `MonthPicker` | 固定向前 24 个月，月模式与其他报表割裂 | 仅月模式改用共享导航；其他时间模式保持原实现 |
| 三个页面各自的本地月份状态 | 路由与子页签切换后可能产生不同月份 | 唯一持久化键 `store.report.active-month.v1` |
| 总月报无参数路由进入 | 进入独立路由时丢失工作台上下文 | `/monthly-summary?month=YYYY-MM` |

没有保留注释占位或兼容双选择器。旧选择器函数已删除，旧固定月份循环已删除。

## Bug 根因

旧设计同时存在三个独立状态源：总月报本地状态、经营分析本地状态、账户本地状态。它们分别生成固定数量的自然月份，未读取业务数据边界；总月报还是独立路由，未接收工作台选择的月份。由此会产生三类问题：

1. 用户在一页选中历史月份，切到另一页时重新显示当前月或该页默认月。
2. 单页数据缺失时，未来若开发者以“最近一份数据”回填状态，会造成无数据月份被静默跳过。
3. 不同日期格式（`YYYY/MM`、`YYYY-MM-DD`、中文月份）若直接比较，会遗漏月份或扩大边界。

## 防回归规范

> 月份是跨模块业务上下文，不是页面显示偏好。任何月度页面只能消费或更新统一业务月，不能以自己的最新数据替代用户选择。

1. 新月度页面必须使用 `useReportMonthNavigation`；禁止新增固定“最近 N 个月”循环。
2. 月份边界必须通过纯函数从业务月份并集派生，禁止由当前页面单独派生。
3. 空数据以 `hasData(selectedMonth)` 决定显示内容；禁止 `setMonth(latestMonth)`。
4. 所有跨路由入口必须传递 `month` 参数；无参数链接兼容读取持久化月份。
5. 年、日、自定义范围属于独立时间语义，可保留，但切回月模式必须恢复共享业务月。
6. 每次改动至少覆盖：边界归一化、空数据不跳月、路由月份保持、移动端 320/375/430pt 无溢出。

## 扩展边界

`dish-analysis.tsx` 与 `period-analysis.tsx` 是独立深度分析路由，前者以导入快照列表、后者以时段/日级分析为主。本轮不强行迁移它们，避免误伤其不同时间语义；后续若需要统一入口，应直接复用新的业务月份组件和 Hook，不得复制旧固定 Chip 逻辑。
