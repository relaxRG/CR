# 系统定义一致性复核报告

## 审计范围与结论

本次复核覆盖薪资、补贴、绩效、月度状态、强制重算、同步组成员资格、权限键和认证错误码。生产计算代码、数据模型、页面文案、导出、Worker接口与自动化测试均以同一术语矩阵为基准。

> **结论：** 薪资公式主链已统一为 `settlePayrollExtras()` → `buildPaySlipDraft()` → DRAFT卡片解析/冻结快照。生产代码未发现 `performanceBonus`、`salesCommission`、`业绩提点`或“绩效奖金”作为现行计算、存储或展示字段。发现的一处文档定义歧义已修正：**绩效补贴不是仅页面分组，而是补贴合计、工作绩效和业绩绩效的总和。**

## 薪资术语唯一矩阵

| 术语 | 唯一公式 | 权威结算/存储 | DRAFT展示 | FROZEN/ADJUSTING展示 |
|---|---|---|---|---|
| 补贴合计 | 餐补 + 交通补贴 + 其他补贴 | `settlePayrollExtras()`；三项薪资单字段 | 以实际出勤和控制字段实时结算 | 持久化快照 |
| 工作绩效 | 所有已选工作KPI档位金额之和 | `workKPIBonus` | 唯一结算引擎 | `workKPIBonus`快照 |
| 业绩绩效 | 所有业绩规则按实绩和档位结算之和 | `revenueKPIBonus` | 唯一结算引擎 | `revenueKPIBonus`快照 |
| 绩效补贴 | 补贴合计 + 工作绩效 + 业绩绩效 | 派生值，不新增旧聚合字段 | 绩效补贴页顶部汇总 | 从分项派生 |
| 奖惩小计 | 人工奖励/处罚项目金额之和 | `rewardPenalty` | 读取人工确认项 | 快照 |
| 综合额外 | 绩效补贴 + 奖惩小计 | 派生值，不独立作为权威存储 | 薪资卡五列分项合计 | 冻结分项合计 |
| 应发工资 | 考勤工资 + 综合额外 + 调休兑现 | `grossSalary` | `buildPaySlipDraft()` | 快照 |
| 实发薪资 | 应发 - 社保 - 公积金 - 个税 - 已预支 - 备用金已付 | `finalSalary` | `buildPaySlipDraft()` | 快照 |

## 月度状态定义

| 状态 | 语义 | 允许操作 | 禁止操作 |
|---|---|---|---|
| DRAFT | 所选月尚未确认发薪的实时草稿 | 自动对账、重新计算所选月草稿薪资 | 跨月删除、覆盖其他月 |
| FROZEN | 已确认发薪的正式归档基线 | 查询、开启差额调整 | 自动重算、强制重算、静默覆盖 |
| ADJUSTING | 基于FROZEN基线的隔离差额会话 | 生成/确认差额 | 改写冻结基线 |

“本月”在所有新交互中应写为“所选月（YYYY年M月）”，避免用户浏览历史月份时产生自然月歧义。

## 强制重算定义

正式名称为 **重新计算所选月草稿薪资**。它不是“刷新页面”，也不是“清空所有数据”。它只对DRAFT月执行：先创建本地快照，再根据当前考勤、补贴规则、KPI选择、业绩实绩、预支和扣除重建薪资单，并用一次批量替换写入。

跨月异常不由当前月按钮删除；应扫描为异常清单后逐月处理。DRAFT重算、FROZEN走差额调整、ADJUSTING在调整会话内处理。

## 同步与权限定义

| 概念 | 定义 | 稳定码/边界 |
|---|---|---|
| 当前成员资格 | 本机`deviceId + deviceToken`属于一个同步组的有效成员关系 | 缺失/失效：`SOURCE_MEMBERSHIP_UNAVAILABLE` |
| 未配对本地模式 | 没有成员资格时仅本机持久化，不自动创建同步组 | 可显式创建或加入 |
| 恢复加入 | 来源成员失效时，经二次确认，以目标一次性码创建全新目标身份并仅拉取替换 | 不能因普通401、超时或5xx自动触发 |
| 设备模块权限 | `allowed_keys`定义同组设备可拉取和推送的模块范围 | 刷新后先持久化再决定本轮同步 |

## 旧路径清理

| 旧定义/路径 | 当前处置 |
|---|---|
| `performanceBonus` / `salesCommission` | 加载时物理删除；禁止读取、展示和回退 |
| “业绩提点” | 语义并入业绩绩效，不单列 |
| 薪资卡直读旧额外项聚合 | 已由DRAFT唯一解析和对账替代 |
| 内联累计税公式 | 已提取到 `payroll-draft-reconciliation.ts` |
| 静态本地PDF Worker | 已删除，H5按需加载浏览器Worker |
| Worker原始异常/余额/邮件日志 | 已替换为固定脱敏诊断码 |

## 仍需在未来Worker事务上线时补齐

客户端已覆盖同设备同月锁。跨设备同时发起“重新计算所选月草稿薪资”仍需Worker/D1的租约与修订号CAS；正式API和错误码已在 `payroll-force-recalculation-api-and-concurrency-design.md` 定义。上线前必须完成双设备同revision竞争、租约过期、网络断开和审计不可变性测试。
