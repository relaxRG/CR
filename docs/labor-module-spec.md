# Cocktail R 员工管理与薪资引擎功能说明文档

本文档全面梳理了 Cocktail R 员工模块（`labor`）的所有功能、细节及交互逻辑。在梳理过程中，我们对核心计算引擎进行了正确性校验，并修复了部分边缘时序 Bug。

---

## 一、 员工档案与基础设置

员工档案是整个薪资计算引擎的基础数据源，支持高度定制化的差异化配置。基础信息涵盖了员工姓名、代号（如英文名）、手机号、身份证号、入职与离职日期等核心字段。在证件管理方面，系统允许上传身份证正反面以及健康证照片，并支持设置健康证到期日提醒以确保合规性。此外，员工支持绑定多张银行卡并设定默认收款卡，薪资单导出时会自动拉取默认卡信息以便于财务打款。

为了适应复杂的餐饮门店组织架构，系统在部门与人员类型上提供了极大的灵活性。

| 配置维度 | 详细说明 |
| :--- | :--- |
| **部门归属** | 内置前厅、后厨、兼职、其他四大类。支持创建**自定义部门**（如“一楼前厅”、“二楼吧台”），并可为其分配专属颜色和排序权重。排班表和员工列表将严格按照自定义部门进行分组显示。 |
| **员工类型** | 分为全职（Fulltime）、长期兼职（Longterm Parttime，拥有固定排班和月薪，支持预支）和临时兼职（Parttime，按次或按小时计费，无固定排班）。 |
| **基本薪资** | 全职与长期兼职设定月度底薪（Base Salary），临时兼职则设定固定时薪。 |
| **工时规则** | 除了支持设置全局标准日工时（如每天 8 小时）外，还支持**灵活工时规则**（Weekly Hours Rules）。例如可设定周一至周四每天 8 小时，周五至周日每天 10 小时。引擎在计算每日加班时，会自动匹配当天的对应规则。 |
| **休息天数** | 设定每月的法定带薪休息天数（如每月 4 天），系统将据此自动推算该员工当月的“应出勤天数”。 |

## 二、 薪资附加项：补贴、绩效与奖惩

员工模块支持多类结构化的可变薪资配置，这些配置统一在「绩效补贴专页」中进行管理。所有的交互均采用即时计算机制，管理者的任何勾选或数值输入都会立刻持久化并反映在薪资单草稿中，彻底消除了“忘记保存”的风险。

| 附加项类别 | 适用场景与规则结构 | 交互与发放逻辑 |
| :--- | :--- | :--- |
| **补贴规则** (Allowance) | 支持固定交通补贴、按出勤天数计算的饭补（如 15元/天）以及自定义固定补贴。发放周期支持按月、按季度、按年发放。季度和年度补贴可选择**自然周期**（如 3、6、9、12月）或**滚动周期**（从生效月起每 N 个月发放）。 | 默认按规则自动计算当月应发金额；管理者可在页面中手动勾选或取消某项补贴在当月的生效状态。 |
| **工作绩效** (Task-based KPI) | 适用于主观评分或具体的任务达成考核。支持自定义多个金额档位（例如“优秀 +500”、“合格 0”、“不合格 -200”）。 | 在绩效页中通过单选按钮选择实际达成的档位，金额即时汇总并写入薪资单。 |
| **业绩绩效** (Revenue-based KPI) | 适用于基于门店营业额的提成考核。可绑定总营业额、净收入、净利润或特定经营大类（如“酒水类”）。计算模式支持固定金额或按比例提成（如 4%）。 | 发放模式支持“叠加发放”（达到多个档位时金额累加）和“取最高档”（只拿最高一档金额），并支持设置封顶。管理者输入实际达成金额后，系统自动匹配档位计算奖金。 |
| **临时奖惩** (Reward & Penalty) | 用于处理日常突发的奖励或罚款。在员工薪资卡片的主界面中直接编辑。 | 支持添加多条文本明细（如“全勤奖 +200”、“迟到扣款 -50”），系统会自动将所有条目汇总为正负值并计入当月应发薪资。 |

## 三、 排班与考勤计算引擎

排班表不仅是出勤记录的载体，更是驱动底层薪资单生成的全自动引擎。在交互设计上，排班表采用了横向无限滚动的 Excel 风格视图，按周分组显示日期，并对跨月日期进行了自动淡化处理。管理者可以在“班次模式”（显示午班/晚班标签）和“时长模式”（显示具体工时数字）之间无缝切换。此外，系统支持框选多个格子进行批量删除，并提供了一键“快速填充”功能，将特定班次模板快速应用到员工的整月工作日中。

排班表中的每一次状态变更都会触发薪资引擎的重算。引擎通过解析特殊状态的方向、是否计入工时以及薪资倍率，自动推导考勤工资。

| 核心机制 | 逻辑与计算说明 |
| :--- | :--- |
| **特殊状态解析** | 引擎将特殊状态分为三类。**缺席类（Negative）**：如旷工（扣 2 倍日薪）、病假（退回 0.5 倍日薪）、事假（扣 1 倍日薪，无额外调整）。**工作日类（Positive）**：如节日上班（算实际工时，额外补偿 2 倍日薪）。**中性类（Neutral）**：如普通休息或加班换休（不计工时，不加不扣薪）。 |
| **调休与补偿** | 当员工加班超过设定阈值（如 4h）时，系统会自动提醒将其存入“换休余额”（有效期 3 个月）。排班时若选择“加班换休”，系统将自动扣除相应余额。对于节日上班产生的多倍薪资，默认处理为“拿钱”，但也可分配为“换休”，产生有效期至下月末的节假日调休余额。过期的余额支持手动兑现成现金。 |
| **考勤工资推算** | 考勤工资遵循五格加法公式：`考勤工资 = 比例底薪 + 加班工资 + 节日补偿 - 特殊状态惩罚`。其中，比例底薪等于 `底薪 × (实际出勤天数 / 应出勤天数)`。 |
| **无来源多休** | 当员工实际出勤天数小于应出勤天数，且没有换休余额可供抵扣时，其比例底薪会自动按比例减少，系统不会施加额外惩罚。同时，系统会生成“无来源多休提醒”，交由老板人工确认是否特批不扣薪。 |

## 四、 薪资单生成与全局税费

每次排班修改、预支新增或补贴调整，引擎都会在 500ms 防抖后调用 `buildPaySlipDraft` 自动重算当月薪资单草稿。实发薪资的计算严格遵循以下公式：`实发薪资 = 应发薪资(含奖惩、绩效、兑现) - 社保个人部分 - 公积金个人部分 - 个人所得税 - 薪资预支 - 备用金人工已付`。

在合规性税费扣除方面，系统提供了高度自动化的双轨制计算支持。

| 税费模块 | 自动化与计算逻辑 |
| :--- | :--- |
| **社保与公积金** | 系统内置了北上广深等主流城市的 2025 年社保基数上下限及比例政策，支持输入城市名一键自动填充。计算采用双轨制，同时算出个人缴纳部分（从员工工资中扣除）和公司缴纳部分（计入公司人力总成本）。开关和比例支持全局默认设置，也允许在单名员工档案中进行独立覆盖。 |
| **个人所得税** | 采用中国标准的累计预扣法。系统会自动扫描该员工当年的历史薪资单，累加“已税收入”和“已预扣税额”。支持自定义起征点（默认 5000 元）和专项附加扣除金额，最终通过 7 级超额累进税率表自动推算当月应缴个税。 |

## 五、 薪资预支与备用金联动

薪资预支功能拥有独立的管理页面，用于记录员工的临时借款。每一笔预支记录都会经历明确的状态流转：从 Pending（待扣除），到 Deducted（已在薪资单中扣除），或是 Cancelled（取消）。

为了打通门店日常支出与员工薪资的账目，系统引入了备用金智能关联机制（Petty Cash Link）。系统会自动扫描当月备用金记录中分类为 `K1` 或 `K9`（人工相关）的条目，并通过 NLP 别名匹配技术解析备注内容（例如“预支给阿杰 500”），从而自动定位对应的员工档案并建立关联草稿。当老板在预支页面“一键确认”这些草稿后，该笔备用金支出将直接计入员工当月的「已预支」（备用金部分），在发薪时从实发薪资中自动扣除，确保门店现金流与人力成本账目不重不漏。

## 六、 离职归档与数据安全

在员工生命周期管理中，数据的一致性与安全性是设计的核心。当员工离职时，管理者只需点击“归档”，该员工便会从主列表和排班表中隐藏，不再参与未来的排班调度。然而，为了保证过往经营分析和财务报表的绝对准确，归档员工的所有历史排班、薪资单和月报数据将被**永久保留**。如果员工重新入职，管理者可以在归档列表中一键将其“恢复在职”。

系统同时提供了“彻底删除档案”的选项，但这仅建议在员工信息确实录入错误时使用。值得注意的是，即便执行了彻底删除操作，该员工名下已生成的历史薪资单和排班记录依然会作为“快照”存在，历史薪资单上仍会如实显示其当时的姓名和代号，从而彻底杜绝了因人员删除导致历史账目对不上的风险。

## 附：本次审查修复的 Bug 记录
在梳理交互逻辑时，我们发现并修复了一个薪资重算的时序 Bug：
- **Bug 描述**：在员工薪资卡片中保存“奖惩明细”时，实发薪资更新了，但“税前应发（grossSalary）”未包含新录入的奖惩金额。
- **根因**：原代码先调用了 `buildPaySlipDraft`，然后再将新奖惩写入 Store。由于 `buildPaySlipDraft` 内部从 Store 读取旧的奖惩总额来计算 `grossSalary`，导致应发金额滞后。
- **修复方案**：调整执行顺序，先将新奖惩金额 `upsert` 到 Store 中，然后再调用 `buildPaySlipDraft` 重算整张薪资单，确保所有字段严格一致。该修复已在 commit `fd286b0` 中提交并全量通过测试。
