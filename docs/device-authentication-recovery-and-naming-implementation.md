# 设备认证恢复、同步组创建与设备命名实现说明

**状态：已实施，待发布新客户端版本。**

## 1. 根因与修复范围

设备管理在没有成员资格时只显示“设备组（0台）”空状态，但没有“创建新的同步组”操作。因此，用户既不能创建独立组，也无法在该界面完成初始化。与此同时，已保存但服务端失效的来源成员资格在 `/api/device/prepare-switch` 中被统一返回为 `Unauthorized`；客户端原样弹出 `Error: Unauthorized`，无法判断这是目标码错误、网络问题还是可恢复的来源身份失效。

本次修复将这两类状态明确分开：未配对本地模式提供显式创建/加入选择；已配对但来源身份失效时仅在用户再次确认后启用恢复加入。启动、重试、前后台切换仍绝不会隐式创建主设备。

## 2. 认证错误码与日志规则

| 场景 | Worker错误码 | 客户端行为 | 日志边界 |
|---|---|---|---|
| 来源设备令牌失效 | `SOURCE_MEMBERSHIP_UNAVAILABLE`（401） | 显示恢复加入二次确认 | 追加脱敏 `switch_prepare_failed`；Worker仅记录是否存在设备ID |
| 目标码无效、过期、占用 | `PAIR_CODE_UNAVAILABLE`（400/409） | 指引在目标主设备重新生成码 | 不记录配对码 |
| 目标与来源相同 | `TARGET_GROUP_SAME_AS_SOURCE` | 告知无需切换 | 仅错误码 |
| 主设备未交接 | `OWNER_HANDOFF_REQUIRED` | 要求选择活跃新主设备 | 仅错误码与脱敏组提示 |
| 恢复加入写入失败 | `RECOVERY_JOIN_WRITE_FAILED` | 保持写入屏障并允许重试 | 不记录令牌、业务内容或原始请求体 |
| 当前设备认证失败 | `DEVICE_AUTH_UNAUTHORIZED` | 引导回设备管理恢复 | 仅错误码 |

客户端诊断日志最多保存120条，组ID经过不可逆短哈希处理；不保存令牌、配对码、业务数据、完整服务端响应或照片内容。Worker诊断同样只记录安全事件名、组ID前缀和角色。

## 3. 安全恢复加入

正常切组仍使用原子准备、交接、提交和目标完整水合。只有Worker明确返回 `SOURCE_MEMBERSHIP_UNAVAILABLE` 时，页面才显示“确认恢复加入”。恢复流程先写加密本地快照、启用写入屏障并停止旧轮询；随后 `recover-join` 仅使用目标一次性码创建**全新的目标设备ID/令牌**，完整下载目标组快照并只下载目标照片。A组数据、脏队列、时间戳和旧照片目录都不会上传至B组。

网络超时、5xx、任何其他401和普通配对错误都不会自动降级为恢复加入。恢复过程中强退后：若新目标身份已落盘，只能继续目标水合；若尚未创建目标身份，则安全释放屏障回到本地模式，等待用户重新明确确认。

## 4. 创建同步组和设备命名

设备管理的未配对卡片提供“创建新的同步组”和“加入已有同步组”两个显式操作。创建操作经确认后调用 `createNewSyncGroup()`，创建完成立即启动同步并显示邀请入口。

默认展示名称来自 `expo-device` 的公开 `modelName`，例如 `iPhone 15 Pro` 或 `Pixel 8`；不可用时回退到 `iPhone`、`Android`、`Web 浏览器` 或 `设备`。该名称只用于展示，不读取序列号、广告ID或用户Apple设备名。用户可以在设备管理页随时重命名；Worker在当前组内持久化名称、按同名自动添加序号，并发布组级刷新信号。名称绝不改变设备ID、令牌、角色、权限或同步组。

## 5. 验证覆盖

- `tests/device-group-entry-recovery-and-name.test.ts`：创建入口、型号名、错误码、恢复端点与名称边界。
- `tests/group-switch-state-machine.test.ts`：恢复加入仅水合目标组；网络失败保留屏障且不回退。
- `scripts/group-switch-worker-chaos.py`：来源成员失效后的恢复加入不读取/不推送A组数据，且目标码只消费一次。
- 现有未配对启动、设备切组UI、权限刷新、同步组隔离测试继续覆盖不隐式注册与跨组隔离。

新客户端代码需要随下一版iOS/Android构建发布；Worker端将在部署后立即提供稳定错误码、恢复加入和改名接口。
