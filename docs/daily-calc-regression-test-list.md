# 薪资与补贴（按天/按时计算）回归测试清单

本文档旨在为 cocktail-r 项目中所有涉及「按天计算」和「按时计算」的薪资逻辑提供标准化的回归测试清单。在后续进行薪资引擎迭代时，请逐一验证以下测试用例。

## 一、补贴计算（Allowance）

### 1. 自定义补贴规则验证

自定义补贴（`custom_fixed`）支持多种单位配置，必须确保在不同的出勤天数下，计算引擎能够正确识别单位并执行相应的乘法或固定额逻辑。

| 用例编号 | 测试目标 | 配置参数 | 预期计算结果 |
| :--- | :--- | :--- | :--- |
| **A1** | 按月固定额（`per_month`） | 全勤奖 ¥500，单位 `per_month` | 无论出勤天数为 0、15 还是 26 天，金额始终为 ¥500 |
| **A2** | 按天计算额（`per_day`） | 餐补 ¥30，单位 `per_day` | 出勤 26 天时金额为 ¥780（30 × 26）；出勤 0 天时为 ¥0 |
| **A3** | 补贴类别归属（`per_day`） | 任意补贴 ¥30，单位 `per_day` | 该笔金额必须被归入 `mealAllowance`（餐补），禁止归入 `otherAllowance` |

### 2. 季度与年度周期补贴验证

周期性补贴（`per_quarter` / `per_year`）必须在正确的月份触发发放。引擎通过 `shouldPayAllowanceThisMonth` 函数进行月份拦截，未到发放月的补贴必须返回 0。

| 用例编号 | 测试目标 | 配置参数 | 预期计算结果 |
| :--- | :--- | :--- | :--- |
| **B1** | 自然季度拦截（`natural`） | 季度奖金 ¥1500，单位 `per_quarter`，模式 `natural` | 仅在 3、6、9、12 月份的薪资单中包含此补贴；其他月份为 ¥0 |
| **B2** | 滚动年度拦截（`rolling`） | 周年奖金 ¥5000，单位 `per_year`，模式 `rolling`，生效月 `2025-08` | 仅在 `2026-07`（满12个月）的薪资单中包含此补贴；其他月份为 ¥0 |

## 二、时薪与兼职工资计算

兼职与全职员工的工资计算路径完全不同，需要分别验证时薪提取逻辑和比例底薪折算逻辑。

| 用例编号 | 测试目标 | 配置参数与操作 | 预期计算结果 |
| :--- | :--- | :--- | :--- |
| **C1** | 兼职时薪提取正确性 | 员工类型 `parttime`，普通时薪 ¥35，加班时薪 ¥50；排班产生 10 小时工时 | `attendanceSalary` 必须等于 ¥350（强制使用普通时薪 `hourlyRate` 计算），禁止使用加班时薪 |
| **D1** | 全职比例底薪折算 | 底薪 ¥10000，当月应出勤 27 天；实际出勤 20 天 | 比例底薪必须等于 ¥7407.41（10000 × 20 / 27），按实际出勤比例折算 |
| **D2** | 全职加班工资计算 | 加班时薪 ¥50；产生 5 小时计费加班 | 加班工资 `overtimePay` 必须等于 ¥250 |

## 三、时序与异常边界

在极端数据或异步保存场景下，引擎必须具备健壮的容错机制。

| 用例编号 | 测试目标 | 触发场景 | 预期引擎行为 |
| :--- | :--- | :--- | :--- |
| **E1** | 零出勤天数除零保护 | 由于请假或数据异常，实际出勤天数为负数或 0 | `calcDailyRate` 必须直接返回 0，禁止抛出 `NaN` 或 `Infinity` |
| **E2** | 整页保存时序安全 | 在绩效补贴编辑页，修改补贴生效状态并保存 | 必须先原子写入控制字段（`allowanceOverrides`），再调用 `buildPaySlipDraft` 触发重算，确保薪资总额包含最新改动 |
