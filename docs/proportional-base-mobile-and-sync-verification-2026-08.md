# 比例底薪日薪化：自动重算与移动端验证记录

**验证日期：** 2026-08-11  
**范围：** 比例底薪、未冻结月自动重算、移动端 H5 布局与性能回归。

## 自动重算范围

自动同步只处理当前排班视图月份，并在排班和员工存储均加载完成后以 500ms 防抖执行。状态口径已收敛到 `shouldAutoSyncPayrollMonth`：`DRAFT` 与 `ADJUSTING` 允许自动重算，`FROZEN` 禁止任何自动写入。

| 月度状态 | 是否自动重算 | 业务含义 |
|---|---:|---|
| `DRAFT` | 是 | 未确认月；排班、员工、预支、调休、节假日和全局配置变动后重算。 |
| `ADJUSTING` | 是 | 已确认后进入调整流程；允许生成当前受控草稿。 |
| `FROZEN` | 否 | 已确认发薪；保留正式历史结算，只能通过差额调整处理。 |

对于每位在职且未归档员工，空排班也会进入考勤计算并明确写入出勤 0、比例底薪 0 与考勤工资 0，从而清除未冻结月份的历史残留。总应发仍可能因固定补贴、绩效、提点、奖惩或调休兑现非零，必须逐项追溯，不得把它误判为比例底薪残留。

## H5 移动端验证

静态 Web 导出成功，包含 101 条路由。通过带 SPA 路径回退的静态服务打开 `/labor`，在 Chrome DevTools Protocol 中分别施加 375pt、390pt、430pt 设备指标。

| 设备宽度 | 根节点宽度 | 根节点滚动宽度 | 根级横向溢出 | 结论 |
|---:|---:|---:|---|---|
| 375pt | 375pt | 375pt | 否 | 通过；薪资统计卡、月份切换、员工空态未见截断。 |
| 390pt | 390pt | 390pt | 否 | 通过。 |
| 430pt | 430pt | 430pt | 否 | 通过。 |

三页模块切换容器与排班周视图存在受控的嵌套水平滚动，分别用于模块左右切换和宽排班表查看；它们没有传导为页面根级横向滚动。多设备视觉回归还覆盖 4 格、5 格金额卡与长金额的字体缩放策略。

> 开发服务器模式曾因动态 bundle 的 `Failed to fetch` 出现 Expo RedBox；改用静态生产构建后问题消失。因此该错误归因为开发服务生命周期/动态加载环境，不属于生产静态 H5 构建错误。

## 性能与状态同步验证

视觉、员工薪资表单、考勤面板、空排班清理和多模块同步性能测试均通过。18 个模块在模拟 200ms 网络延迟下串行同步实测约 3.61 秒；自动同步使用 500ms 防抖，并使用 ref 读取最新薪资单控制字段，避免路由返回或连续操作时使用旧闭包。

## 仍需真机回归的场景

当前验证会话没有员工、排班或确认记录，因此 H5 页面只能验证空态和容器布局。发版前 QA 应在 iPhone 真机或 Expo Go 中执行：添加员工 → 写入排班 → 等待自动重算 → 清空排班 → 确认归零 → 冻结 → 修改排班后确认不重算 → 进入调整中后确认可重算。
