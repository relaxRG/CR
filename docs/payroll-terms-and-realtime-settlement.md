# 薪资术语与实时结算规范

> **唯一原则：** 每个金额只拥有一个业务含义、一个存储分项和一个结算入口。页面只展示结算结果，禁止自行重算或将多个概念混用。

## 固定术语与公式

| 名称 | 固定含义 | 计算方式 | 展示位置 |
|---|---|---|---|
| **补贴合计** | 所有补贴规则的结算结果。 | `餐补 + 交通补贴 + 其他补贴`。其中按天补贴必须为`日金额 × 实际出勤天数`，零出勤为零。 | 绩效补贴页、薪资统计卡、考勤薪资详情、导出。 |
| **工作绩效** | 员工工作KPI规则中所选档位产生的奖惩。 | 所有已启用工作KPI档位金额之和。 | 绩效补贴页、薪资统计卡、考勤薪资详情、导出。 |
| **业绩绩效** | 与经营业绩相关的唯一奖励概念。 | 所有已启用业绩规则按实绩和档位计算的金额之和；固定档与比例档均在同一规则引擎计算。 | 绩效补贴页、薪资统计卡、考勤薪资详情、导出。 |
| **绩效补贴** | 不含人工奖惩的员工绩效与补贴结算结果。 | `补贴合计 + 工作绩效 + 业绩绩效`。 | 绩效补贴页顶部汇总。 |
| **奖惩小计** | 与补贴、工作KPI、业绩规则无关的人工奖励或处罚。 | 人工奖惩项目金额之和。 | 薪资统计卡、考勤薪资详情、导出。 |
| **综合额外** | 考勤工资之外、用于计入应发工资的实时附加金额。 | `绩效补贴 + 奖惩小计`。 | 薪资统计卡、考勤薪资详情、导出。 |

## 已删除概念

| 已删除名称 | 处理方式 |
|---|---|
| `performanceBonus` / “绩效奖金” | 已删除。不得作为合并金额存储、读取、回退或展示。 |
| `salesCommission` / “业绩提点” | 已删除。其业务含义并入**业绩绩效**，不得再次单列或重复计入。 |
| “业绩” | 已替换为**业绩绩效**，避免与营业额、业绩实绩或提成混淆。 |

## 唯一实时结算流程

1. 绩效补贴编辑页只保存控制字段：补贴启用状态、工作KPI档位和业绩实绩。
2. `settlePayrollExtras()` 使用员工规则、月份、实际出勤和控制字段计算全部金额及分项审计明细。
3. `buildPaySlipDraft()` 以该结果生成薪资单、应发工资与实发工资。
4. 薪资统计卡、考勤薪资详情、绩效补贴只读页和Excel/PDF导出只读取这两个绩效分项和三个补贴分项。
5. 考勤变化、保存返回和自动同步均重新调用同一结算入口；冻结月份只能产生差额调整，不能静默覆盖归档。

## 关键边界

| 场景 | 必须结果 |
|---|---|
| 实际出勤为0 | 所有按天补贴为0；不得继承旧月份或旧薪资单金额。 |
| 保存工作KPI或业绩实绩 | 薪资统计卡同一状态更新后立即显示新分项，无需离开页面。 |
| 自动同步考勤 | 仅按规则重算金额；不得丢失补贴启用状态、工作KPI档位或业绩实绩。 |
| 已确认发薪 | 不修改归档薪资；通过差额调整保存新旧差异。 |
