# 门店导航架构重构与分析报告

## 一、重构背景与问题分析

在重构前，门店模块（`app/(tabs)/store.tsx`）存在过度嵌套和层级过深的问题：

1. **视觉层级冗余**
   页面顶部同时存在 34px 大标题（动态显示「运营/当月月报/库存管理」）、三大主 Tab、以及二级子 Tab，导致移动端屏幕上半部分被大量导航元素占据，有效内容区域被严重压缩。
2. **操作路径过长**
   用户高频使用的「备用金」和「员工管理」被隐藏在「运营」主 Tab 下；「经营分析」被隐藏在「当月月报」主 Tab 下，用户每次访问都需要至少点击两次。
3. **状态管理复杂**
   维护了 `MainTab`、`MonthlyTab`、`OperationsTab` 三套独立的状态，以及 `MonthlyModule` 和 `OperationsModule` 两个中间层组件，增加了状态同步的复杂度和内存开销。

## 二、重构方案实施

本次重构彻底废弃了嵌套结构，实施了完全扁平化的顶级导航方案：

1. **删除冗余视觉元素**
   删除了顶部的动态大标题，释放了约 60px 的垂直空间。
2. **扁平化顶级 Tab**
   将原来的三层结构合并，直接在顶部提供四个平级的核心模块：
   - **报表**（直接展示经营分析与数据总览）
   - **员工**（直接嵌入薪资统计与排班系统）
   - **备用金**（直接进入备用金管理面板）
   - **库存**（保持原有 10 大品类进销存入口）
3. **功能入口降级与独立化**
   原嵌在「当月月报」下的「账户」子 Tab，现已被抽取为独立的路由页面（`app/store-accounts.tsx`），并在「报表」Tab 的功能入口列表中提供快捷访问路径，避免了与核心分析报表抢占首屏空间。
4. **清理历史包袱**
   删除了 138 行旧代码，移除了 `OperationsModule` 等中间层组件，重置了持久化状态键（从 `store.main.tab.v2` 升级为 `v3`），确保用户本地缓存不会与新结构冲突。

## 三、开发规范建议

为防止后续开发再次出现导航嵌套过深的问题，特制定以下 UI/UX 开发规范：

1. **扁平化优先原则**
   - 移动端应用的顶级 Tab 不应超过 5 个。
   - 严禁在主 Tab 下再嵌套横向滑动的子 Tab 栏（Segmented Control 除外，但仅限于同一页面内的数据过滤，不能作为页面级导航）。
2. **核心路径最短化**
   - 高频操作（如排班、记账）必须在进入模块后 **0 次额外点击** 即可看到。
   - 低频操作（如账户余额对账、历史报表导入）应通过页面底部的「功能入口」列表或独立按钮跳转，而非占据顶层导航栏。
3. **状态清理规范**
   - 当导航结构发生破坏性变更时，必须升级持久化状态的键名（如 `v1` -> `v2`），以防止旧版本客户端读取到非法的 Tab 键值导致白屏。
   - 必须使用 `grep` 或全局搜索彻底清理被废弃的子组件和路由引用。

## 四、测试验证

- **TypeScript 严格模式**：通过（零类型错误，证明所有旧组件引用已被清理）。
- **路由连通性**：四个顶级 Tab 切换正常，新的独立账户余额页面（`/store-accounts`）跳转正常。
